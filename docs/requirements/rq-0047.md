# RQ-0047 — Releases are part of the record

The record knows what was asked, built, tested and decided — but not what *shipped*. A release is
the missing artifact: what went live, when, from which stories, at which commit. Like everything
else in the record it is a document in the bundle, so "what is actually out there" is answerable by
reading, not by remembering. Whether Release enters the profile as its own type (the
[Sprint](../profile/sprint.md) precedent) is decided when this schedules — the profile grows when a
requirement asks it to.

## Acceptance criteria

- [AC-1] A publish mints a release in the record: when, the commit, the live URL, and the stories
  it carried since the previous release.
- [AC-2] A release carries plain-language notes drafted by the agent from its stories, editable
  before the release is shared.
- [AC-3] Releases are listed in the workspace, newest first; the latest shows its URL.
- [AC-4] From a release, every story it shipped — and through them the requirements and tests —
  is one link away. Nothing is restated.
