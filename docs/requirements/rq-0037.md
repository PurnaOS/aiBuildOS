# RQ-0037 — Worktree visibility

Worktrees do the building, and the interface barely admits they exist: a row names a story, not
where it works, how far it has got, or whether anything can still be done with it. Every build row
gains its facts — branch, path, sprint, commits ahead of base, last checkpoint time — and the build
listing reports sprint worktrees alongside story ones, so the dock can show dirty, orphaned and
resumable states with a Resume action where one applies.

## Acceptance criteria

- [AC-1] A build row names its branch and worktree path, and carries a sprint chip when the build
  belongs to a sprint.
- [AC-2] A build row shows how many commits its branch is ahead of its base and when it last
  checkpointed; a build with no checkpoints yet says so rather than showing a blank.
- [AC-3] Dirty, orphaned and resumable worktrees are visibly distinct, and a resumable row offers
  a Resume action.
- [AC-4] The build listing reports live sprint worktrees — sprint id, branch, path, dirty state,
  and the stories building off them — alongside story builds.
