# RQ-0049 — Guardrails are enforcement

The record's hard rules — an agent never flips `draft → ready`, never touches `state:` from a
worktree, never edits protected record files — live today as prose in the instruction files
[RQ-0028](rq-0028.md) scaffolds. Prose is a request. Modern harnesses expose hooks: file-side
configuration where a matching action is *denied*, deterministically, before it happens. Where the
connected harness supports hooks, the scaffolding should write the hard rules as hooks too — the
same mechanism as today's seeding, one layer deeper, and at the same moment: the files that
control the harness are part of the codebase from initialization, not an upgrade bolted on later.

## Acceptance criteria

- [AC-1] Initializing a project — create or adopt — writes the record's hard rules as hooks for
  harnesses that support file-side hook configuration, alongside the instruction files it already
  seeds; a project scaffolded before this gains them the next time scaffolding runs.
- [AC-2] With hooks active, an agent's attempt to break a hard rule is denied by the hook — the
  rule holds even when the instructions were ignored.
- [AC-3] On a harness without hook support, scaffolding degrades to today's instructions; no
  project fails to scaffold because its harness is plainer.
- [AC-4] Hook activation rides the harness's own trust flow. Scaffolded hooks never activate
  silently.
