# RQ-0032 — Remote sync

The application branches, commits and merges, but every conversation with a remote still happens in
a terminal. Fetch, pull and push belong in the workspace — riding the user's own git and credential
chain, one press each, exactly as [DC-0023](../decisions/dc-0023.md) settles. Nothing syncs on its
own: no auto-push, no auto-fetch, no background polling. The watcher already sees `.git/refs`, so a
sync that changes refs reaches the screens like any other change.

## Acceptance criteria

- [AC-1] Fetch, pull and push each run only when pressed; nothing contacts a remote unasked.
- [AC-2] Pull is fast-forward only; a diverged branch fails with git's own message rather than
  merging or rebasing behind the user's back.
- [AC-3] Pushing a branch with no upstream retries as `push -u origin <branch>` and publishes it.
- [AC-4] An authentication failure reports as `git_auth` and a missing remote as `no_remote` —
  mapped codes the interface can act on, with git's stderr preserved alongside.
- [AC-5] Sync runs the user's own git binary and credential chain; the application stores no
  credentials and asks for none.
- [AC-6] A fetch or pull that changes refs is reflected in the git surfaces within a debounce, with
  nothing further pressed.
