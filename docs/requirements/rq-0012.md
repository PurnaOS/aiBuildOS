# RQ-0012 — What the validator would say is said in the workspace

The knowledge engine produces findings and the terminal is the only place they land.
[EP-0003](../epics/ep-0003.md) noted the gap on purpose — "no story asks for that screen yet."
This is that requirement. It matters now because the record is about to be written by more hands:
boards flip states, agents mint drafts, and a draft the validator would reject should be marked
where someone is looking at it, not discovered in CI.

The artifact editor already shows findings for the artifact being edited. This extends the same
truth to where artifacts are *listed*, so a problem is visible before anything is opened.

## Acceptance criteria

- [AC-1] Artifacts with validator findings are marked where they are listed, errors told apart
  from warnings, in words and not colour alone.
- [AC-2] Opening a marked artifact shows each finding beside the content it concerns.
- [AC-3] The marks follow the file: they update when the artifact changes, whoever changed it.
- [AC-4] A clean record shows nothing at all — no empty panel, no zero-count badge.
