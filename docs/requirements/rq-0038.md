# RQ-0038 — A shell in the workspace

Running a dev server, tailing a log, poking at the project — today that means leaving the app for
a system terminal. The workspace gets a real one: PTY terminals spawned by a new
`main/terminals.ts` (a registry `t1, t2…`; the shell taken from `$SHELL`, `COMSPEC` on Windows),
spoken over `terminal:open/input/resize/close/list` channels plus `terminal:data/exit` events, and
rendered by an xterm view filling the activity dock's resizable panel — a **Terminals** section of
rows, not a `terminal` TabKind. [DC-0026](../decisions/dc-0026.md) settles the mechanism.

The security stance is deliberate and two-sided. The user's own typed commands need **no
supervision** — this is the same trust they already have in their system terminal, and inserting
an approval prompt between a person and their own shell would be theatre; supervision governs
*agent* commands and is untouched by this requirement. On the other side, the terminal's working
directory is **resolved main-side from the project registry, never renderer-supplied** — a
compromised renderer cannot ask for a shell rooted somewhere else.

## Acceptance criteria

- [AC-1] Opening a terminal from the dock spawns a real PTY running the user's shell
  (`$SHELL`/`COMSPEC`), with its cwd resolved main-side from the project registry — the open
  request carries no path.
- [AC-2] Typed input reaches the shell and its output renders in the dock's xterm view; because
  the child sees a TTY, prompts, colors and interactive programs behave as they do in a system
  terminal.
- [AC-3] Resizing the dock panel propagates the fit-addon's cols/rows to the PTY, and programs in
  it observe the new size.
- [AC-4] Multiple terminals coexist: each registry entry (`t1, t2…`) is a row in the dock's
  Terminals section, and `terminal:list` reports them all.
- [AC-5] Commands the user types run without any supervision prompt; agent command supervision is
  unchanged.
- [AC-6] Every pty is killed on `project:close` and on `before-quit` — closing the project or the
  app leaves no orphan shells.
