# RQ-0042 — One agent-settings surface

Everything that configures the agent is scattered: session mode in one control, the harness's own
options in another, supervision in a third — three pieces of chrome for one question, "how is this
agent set up right now?". They collapse into a single popover, grouped by **origin**, because
origin is the one honest disambiguator: two harness options can legitimately share a name (the
two-MODE collision is real), and guessing which is which by deduplicating names would be lying.

## Acceptance criteria

- [AC-1] One popover holds every agent setting: the ACP session mode, the harness's own options,
  and supervision. No agent setting lives anywhere else.
- [AC-2] Settings are grouped by origin — Session for the ACP session mode, the harness's
  `displayName` verbatim for its options. Two options sharing a name stay distinct through their
  groups; neither is renamed, deduped, or dropped.
- [AC-3] Supervision works inside the popover as it did on its own, and keeps
  `data-testid="supervision"`.
- [AC-4] While supervision is `hands-off`, the popover's trigger shows an amber echo — the state
  is visible without opening anything.
