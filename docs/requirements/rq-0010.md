# RQ-0010 — An artifact changes state only along its type's transitions

The profile declares transitions as data, and nothing reads them. Today the artifact editor
offers every state in the vocabulary, so `draft` can become `done` in one click and the record
happily tells a lie. [RQ-0003](rq-0003.md) put the reason on file: a validator sees one commit
and cannot know the previous state, so transition legality cannot live there. It can live where
the previous state *is* known — the application's own save path, which reads the file before it
writes it.

The same boundary carries the other deferred rule: criterion IDs are append-only, and an editor
that lets `[AC-2]` be renumbered breaks every `RQ-NNNN#AC-2` reference that ever pointed at it.

What this deliberately does not do is police anyone else. An agent or a terminal writes files
directly; a state that arrives that way is displayed as found. Guarding the application's own
door is enforcement; rewriting other people's facts would be corruption.

## Acceptance criteria

- [AC-1] Changing an artifact's state in the workspace offers exactly the transitions its type
  declares from the current state, and nothing else.
- [AC-2] A save that would move a state along an undeclared pair is refused, in words naming the
  pair.
- [AC-3] Every type's retirement wildcard stays available from any state.
- [AC-4] Editing a criteria section cannot renumber or reuse an existing `[AC-n]`; new criteria
  append after the highest number ever used.
- [AC-5] A state written by anything outside the application is displayed as found, never
  "corrected".
- [AC-6] The index row's state cell follows the flip in the same write, as saving already does.
