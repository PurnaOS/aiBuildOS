# RQ-0002 — Projects are created or adopted from local Git repositories and opened from a launch page

aiBuildOS drives coding agents against a repository, but nothing in the product yet says *which*
repository. The app opens on a runtime version table, and [RQ-0001](rq-0001.md) harnesses run in the
user's home directory because there is nowhere better to point them. Sessions, worktrees, previews and
the record itself all need a subject before they can exist.

A **project** is one local directory the user works on, registered so the app can find it again. It is
always a Git repository — [DC-0010](../decisions/dc-0010.md) makes Git the storage layer for the
record and [DC-0015](../decisions/dc-0015.md) makes the record the point, so a project that is not a
repository is a project the product cannot do its job on. A directory the user adopts is initialised
if it is not one already.

Because the repository *is* the record, a project created by aiBuildOS starts with an OKF bundle: the
type profile and the conventions, so the first requirement someone writes in it has somewhere to go
and something to validate against. That bundle holds no artifacts. A new project's backlog is empty,
and [requirement-first development](../guidelines/requirement-first.md) says its first artifact is the
one its first feature needs.

Registering a project is a reference, never a copy: the folder on disk is the project, and this
record is only how the app finds it. Forgetting a project therefore cannot delete anything.

Driving an agent inside the open project is out of scope here — this requirement establishes the
subject, not the work done to it.

## Acceptance criteria

- [AC-1] A project is stored configuration — a name, an absolute local path, and when it was last
  opened — and survives an application restart.
- [AC-2] The application opens on a launch page listing every registered project with its name, path
  and current branch. An empty list is an invitation to create or add one, not an error state.
- [AC-3] Creating a project asks where it should live and what it is called, creates that directory,
  initialises a Git repository in it, and makes one initial commit. An existing directory is never
  written into.
- [AC-4] A created project contains an OKF `docs/` bundle — the type profile, the conventions, a
  bundle README and an index for every artifact directory — over which the knowledge engine reports
  no error-severity findings. The bundle contains no artifacts.
- [AC-5] Adding an existing directory registers it as a project. A directory that is not already
  inside a Git repository is initialised as one; one that is, is left untouched.
- [AC-6] Choosing a location uses the operating system's native directory picker. The user never has
  to type a path, and cancelling the picker changes nothing.
- [AC-7] Opening a project reports its current branch, its working-tree status as counts of staged,
  unstaged and untracked paths, and its most recent commits.
- [AC-8] Opening a project summarises its OKF record as artifact counts by type and by state, and
  distinguishes a project with no bundle from a bundle with no artifacts.
- [AC-9] Forgetting a project removes it from the list only. No file or directory on disk is
  modified or deleted.
- [AC-10] A registered project whose directory has been moved or deleted is listed as unavailable,
  with its path, and can be forgotten. It never prevents the launch page from working.
- [AC-11] Every failure the user can provoke is reported with what failed and why, distinguishing at
  least: Git not installed, Git having no configured identity, the target directory already
  existing, and the location not being writable.
- [AC-12] A directory that is already registered is not registered a second time. Adding it again
  yields the project that already exists.
