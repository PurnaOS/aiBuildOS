# RQ-0008 — Work is saved without being asked, and by the shortcut everyone already knows

Editing here means remembering to press a button that exists nowhere else in the tools this sits
beside. Every editor a developer uses either saves for them or saves on ⌘S, usually both; this does
neither, so the price of forgetting is a confirmation dialog on the way out and, if that is dismissed
wrongly, the work.

Two things follow, and the second is not a detail. **Saving is not free here**: these files are in a
Git working tree, so every write lands in the Git tab and in whatever the agent reads next. That makes
*when* a save happens part of the requirement rather than a tuning constant.

The case that has to be designed rather than discovered is a save that races the agent.
[RQ-0005](rq-0005.md) already refuses to discard either side when the agent writes to a file being
edited — but that machinery assumes an unsaved edit stays unsaved until a person commits to it. A save
that fires on its own while a turn is in flight can overwrite what the agent has just written, before
anyone has been told there was a disagreement at all. So it does not fire then.

The keyboard is the other half. An application that sets no menu inherits the platform's, and gains
copy, paste, undo and select-all for nothing; one that sets its own must put those back, or adding ⌘S
silently costs ⌘C.

## Acceptance criteria

- [AC-1] An edit is written shortly after the user stops typing, without anything being pressed.
- [AC-2] ⌘S — Ctrl+S off macOS — writes what is unsaved immediately, and is offered in the menu where
  a person can find it.
- [AC-3] Nothing is written while a turn is in flight; what was typed during one is written once the
  turn has ended and the file has been reconciled with what the agent did.
- [AC-4] Nothing is written while the user is being asked to choose between their version and the
  agent's. Choosing is what resolves that, not a timer.
- [AC-5] A rapid sequence of edits results in one write of the last of them, not a write for each.
- [AC-6] A save that fails leaves the work in the editor and says what failed, exactly as a save asked
  for by hand does.
- [AC-7] The application's own menu carries the standard editing, window and application commands, so
  copy, paste, undo, select-all, close and quit keep working.
- [AC-8] Closing an editor does not ask about unsaved work, because in the ordinary case there is
  none. It still asks when a write is being held back for AC-3 or AC-4 — that is the one case where
  something really would be lost, and it is the case a guard is for.
