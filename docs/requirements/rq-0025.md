# RQ-0025 — Finished work can be tried, running, beside what asked for it

The vision doc's step 10 in full: "a working version you can click through — right next to the
original request". Review today reads diffs and check verdicts; for anything with a screen, the
only real question is what it feels like to use, and answering that means leaving the
application. [DC-0012](../decisions/dc-0012.md) reserved the mechanism — a dev server as a child
process, rendered in an isolated `WebContentsView`.

How a project runs is declared the way its checks are ([RQ-0019](rq-0019.md)): a fenced block in
a playbook, readable by a person, followable by an agent, runnable by the application — no
configuration format anywhere.

## Acceptance criteria

- [AC-1] A project that declares how it runs and where it serves can be started from a story's
  review and rendered inside the workspace, isolated from the application's own session.
- [AC-2] The preview stands beside the story and its criteria, and closing the review stops the
  server; quitting the application leaves nothing running.
- [AC-3] A server that fails to start reports why, in its own words.
- [AC-4] A project that declares no way to run offers no preview, not a broken one.
