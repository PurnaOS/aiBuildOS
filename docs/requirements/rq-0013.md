# RQ-0013 — The standard steps are buttons the project carries

Everything the vision doc calls a step — turn requirements into a plan, build a story, draft
requirements from an idea — is, mechanically, a prompt to an agent. Today every one of those
prompts has to be typed, which means knowing what to say, which is exactly the expertise the
product promises not to require.

A playbook is that prompt, kept: named instructions the project carries as an ordinary committed
record artifact ([DC-0019](../decisions/dc-0019.md)), shown as a button, composed with whatever
the user has selected, and sent through the conversation in the open. The instructions belong to
the project, not the application — a different tool pointed at the same repository reads the same
rules, which is the vision doc's "keep everyone on the same page" made literal.

The button must be transparent. What was sent is what the transcript shows as the user's own
message; an ⓘ on the button discloses the exact text and the harness it runs with before
anything is pressed.

## Acceptance criteria

- [AC-1] A project carries named playbooks as record artifacts; the workspace shows each active
  one as a button carrying the label the artifact declares.
- [AC-2] Pressing a playbook composes its instructions with the artifacts the user selected as
  context and sends that through the conversation; the transcript shows exactly what was sent.
- [AC-3] Before pressing, a person can see what a button will do: its plain description, the
  harness it will run with, and the exact instruction text.
- [AC-4] A newly created project is seeded with the standard set; a project without playbooks
  shows no buttons and can seed the standard set on request.
- [AC-5] A playbook added or edited as an ordinary artifact appears as a button beside the
  standard ones, indistinguishable in behaviour; editing one requires no application change.
- [AC-6] A playbook names its preferred harness by display name; when no configured harness
  matches, the button runs with the harness the workspace already has attached.
