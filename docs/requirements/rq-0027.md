# RQ-0027 — The record follows the work, however the work happens

Only five paths have ever moved a state, and conversation is not one of them: a story worked on
by talking stays at `ready` forever, and the turn-end walk — which only looks at `building` —
never matches it. The natural way to use the product left the record frozen; the owner's words
were "even after a task is implemented, its status is not changing."

The owner has decided the bounds: working on a ready story moves it; agents may walk **work
states only** on the story they are implementing (`ready → queued → building → review`) — never
`draft → ready`, never verdicts, never Requirement states — and a worktree build's agent stays
hands-off entirely, as [DC-0021](../decisions/dc-0021.md) always said and the build playbook
never got told.

## Acceptance criteria

- [AC-1] "Work on this" on a Story at `ready` or `queued` walks it to `building` through the
  guarded save and sends the build playbook composed with the story and its requirement — the
  same walk the board's Build performs; the turn's end lands it in `review`.
- [AC-2] "Work on this" on any other artifact behaves exactly as before.
- [AC-3] The build playbook carries DC-0021's hands-off line: an agent building in a worktree is
  told, in the playbook it receives, to leave every `state:` field alone.
- [AC-4] Starting a build is one control, not one per harness: a single menu offering the harness
  and here-or-worktree.
