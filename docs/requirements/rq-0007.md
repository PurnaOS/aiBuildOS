# RQ-0007 — The application's appearance can be chosen

The application follows the operating system's light or dark setting and offers no way to disagree
with it. That is the right default and the wrong only option: people work in a dark editor on a light
desktop and the reverse, and an application that insists on matching the desktop is one they have to
change the desktop to change.

The mechanism matters as much as the setting. Electron's `nativeTheme.themeSource` makes the choice at
the platform level, so `prefers-color-scheme` in the renderer changes with it. Everything already
written against that media query — every `dark:` utility, the conversation's palette from
[BG-0002](../bugs/bg-0002.md) — follows with no change at all, and the renderer keeps the browser as
its single authority on which appearance is in force. A class or attribute maintained in the renderer
would be a second answer to a question the platform can answer once.

The choice belongs to the installation, not to a project: it sits with the harnesses in Settings,
which is where things that outlive a project already live.

## Acceptance criteria

- [AC-1] The appearance can be set to follow the system, to light, or to dark.
- [AC-2] Following the system is the default, and the state of a fresh installation.
- [AC-3] A change takes effect immediately, everywhere, without reopening anything.
- [AC-4] The choice survives restarting the application, and is in force before the first frame is
  drawn rather than applied after it.
- [AC-5] With the choice set to follow the system, changing the system setting still changes the
  application.
- [AC-6] The renderer holds no separate record of which appearance is in force: it reads the same
  media query it always did.
