# RQ-0046 — Publish to a live URL

The journey ends one step short. Work is accepted and committed ([RQ-0018](rq-0018.md)), even
pushed ([RQ-0032](rq-0032.md)) — and then the product exists only on this machine. Every tool the
owner's audience compares us to ends at a link someone else can open. Publishing closes that step
from inside the application: an agent-driven deploy through a provider's own CLI, run as a playbook
the project carries, with the resulting URL surfaced where the work is.

Which provider, and how credentials are held, are decisions taken when this schedules — the
requirement is the step, not the vendor.

## Acceptance criteria

- [AC-1] A project with accepted work can be published to a live URL from inside the application,
  as a playbook run — no terminal, no provider dashboard.
- [AC-2] Publishing again updates the same URL; the link a person shared keeps working.
- [AC-3] The URL is visible in the workspace after a publish, and recorded on the release it
  shipped ([RQ-0047](rq-0047.md)).
- [AC-4] A failed publish reports the provider's own words in the workspace; nothing pretends to
  be live that is not.
