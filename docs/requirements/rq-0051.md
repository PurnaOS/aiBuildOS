# RQ-0051 — Playbooks know the harness's commands

A harness arrives with its own named workflows — slash commands it advertises over ACP as
`available_commands_update`, each with a name and description. Today the application is blind to
them: a command typed into the composer passes through as plain text, and nothing lists what the
harness can do. The composer that already homes playbooks ([RQ-0043](rq-0043.md)) should list the
harness's own commands beside them — discovered, described, and invoked as the harness expects.

## Acceptance criteria

- [AC-1] Commands the harness advertises appear in the composer beside the project's playbooks,
  carrying the harness's own names and descriptions, grouped by origin as
  [RQ-0042](rq-0042.md) grouped settings.
- [AC-2] Invoking one sends it as the harness expects, and the transcript renders it as a command
  ([RQ-0031](rq-0031.md)'s card), not as ordinary prose.
- [AC-3] The list is live: a command advertised mid-session appears without a restart, and a
  withdrawn one disappears.
