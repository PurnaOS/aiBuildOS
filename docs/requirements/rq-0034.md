# RQ-0034 — PR status

Once a branch is pushed, the next question is what its pull request is doing — and today that
answer lives in a browser tab. The workspace answers it through the **optional** `gh` CLI, exactly
as [DC-0024](../decisions/dc-0024.md) settles: on demand, argv-only, no token ever stored. A
machine without `gh` is a fact to display, not a failure to recover from.

## Acceptance criteria

- [AC-1] With `gh` installed and a PR open for the current branch, the sync header's PR chip shows
  the PR's number and state.
- [AC-2] With `gh` absent, the result is `gh_missing` data — the chip stays quiet and nothing
  reports an error.
- [AC-3] PR status is fetched only when asked for; no polling loop exists.
- [AC-4] `gh` is invoked argv-only with the user's own authentication; the application stores no
  GitHub token and asks for none.
