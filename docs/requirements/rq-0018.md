# RQ-0018 — Finished work is committed from the workspace

The Git tab reads everything and can change nothing: accepted work sits in the working tree until
someone leaves the application to land it. Writing to Git was deferred on purpose — hooks,
signing, identity, each a way to fail that reading never has — and this is the requirement that
deferral asked for.

The posture is that the application is not a Git client with opinions; it is the user's own Git,
driven by argv ([DC-0010](../decisions/dc-0010.md)). A hook that rejects a commit is not an error
in this application, and its words — not a paraphrase — are what the user reads. And nothing
commits without a person asking: no playbook and no agent triggers a commit, because "you're
always in control" starts with what enters history.

## Acceptance criteria

- [AC-1] Changes the Git tab shows can be staged and unstaged from it, one path at a time.
- [AC-2] Staged changes can be committed with a message, and the new commit appears in the
  history the tab already shows.
- [AC-3] Git runs as the user's own: hooks, signing and identity apply; a hook rejecting a commit
  is reported in the hook's own words, and the work stays staged.
- [AC-4] Accepting a story offers committing its changes, with a message derived from the story;
  declining leaves everything as it was.
- [AC-5] Nothing commits without a person asking; no playbook and no agent triggers one.
- [AC-6] Every Git invocation is argv, never a shell string.
