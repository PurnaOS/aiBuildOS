# RQ-0035 — Sprints

A batch of related stories has no shape today: each builds and merges alone, straight onto main.
A **sprint** gives the batch one — a first-class artifact (`SP-NNNN`, `docs/sprints/`, the profile
grows a `Sprint` type for it) that *is* a branch with its own worktree. Its stories build in
parallel off the sprint branch and merge back onto it; finishing the sprint is one deliberate
merge into main. The whole shape follows [DC-0025](../decisions/dc-0025.md): the `--` branch
binding, record flips staying in the main checkout, and the `stories_live` guard.

## Acceptance criteria

- [AC-1] Starting a sprint from selected ready stories mints the Sprint artifact with
  `contains: [ST-…]`, creates branch `aibuildos/sp-NNNN`, and adds a worktree checked out on it.
- [AC-2] A story built inside a sprint builds on `aibuildos/sp-NNNN--st-NNNN`, branched from the
  sprint branch, and its accepted merge lands on the sprint branch — not on main.
- [AC-3] Finishing a sprint merges its branch into main with `--no-ff`; both finish and discard
  refuse with `stories_live` while any `sp-NNNN--*` worktree survives.
- [AC-4] Record state flips for sprint stories happen in the main checkout only; the sprint
  branch's `docs/` stays byte-identical to its base until the sprint merges.
- [AC-5] The Work header offers a sprint selector that filters the board, a create action over the
  ready checkboxes ("Start a sprint with N stories"), a progress count, and Finish.
- [AC-6] A sprint and its story bindings survive an application restart with no tracked file —
  the branches and worktrees are the whole record.
