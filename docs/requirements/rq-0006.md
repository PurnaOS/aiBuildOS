# RQ-0006 — New files and record artifacts are created from the workspace

[RQ-0005](rq-0005.md) made an existing artifact editable. Nothing can be *started* here: the first
requirement of a project has to be written in another application and discovered by this one, which
makes the workspace a place to amend the record rather than to keep it.

Minting an artifact is not the same act as creating a file, and the difference is the whole reason
this is its own requirement. An artifact has an **identity**: a prefix, a number that is append-only
and never reused, a directory it belongs in, the frontmatter its type requires, the body sections its
type declares, and a row in an index — all of which
[OKF conventions](../guidelines/okf-conventions.md) specifies and the profile
[RQ-0003](rq-0003.md) taught the engine to read. Getting any of it wrong produces a document that
looks like an artifact and is not one, which is worse than not having written it.

So nothing here is hardcoded: the types on offer, the fields written, and the sections scaffolded all
come from the profile. A project whose profile declares types this one has never heard of gets those
types, and a project with no profile is told it cannot mint artifacts rather than being given this
repository's own vocabulary by default.

Writing to Git stays out, as [EP-0004](../epics/ep-0004.md) says: a new file is created and left
untracked, which the Git tab already shows.

**AC-9 was added after the rest shipped.** Creating a file meant typing its whole path from the root
of the project, which is a fine way to *describe* a file and a poor way to make one next to the file
you are looking at. The requirement was incomplete rather than wrong, so it returned to `draft` and
gained a criterion; AC-1 to AC-8 keep their meaning and their verification
([requirement-first](../guidelines/requirement-first.md)).

## Acceptance criteria

- [AC-1] A file can be created at a path chosen by the user, and appears in the file tree without a
  reload.
- [AC-2] An artifact can be created by choosing its type and title, and the workspace allocates the
  next unused number for that type's prefix.
- [AC-3] The artifact is written with the frontmatter its type requires and the body sections its type
  declares, and nothing beyond what the profile and the conventions call for.
- [AC-4] A new artifact is added to its directory index as it is written, so the bundle it joins is
  valid the moment it exists.
- [AC-5] A new artifact opens for editing immediately, without being looked up again.
- [AC-6] The types offered are those the project's profile declares and permits directly; a project
  with no profile is told artifacts cannot be minted there, rather than offered a default vocabulary.
- [AC-7] The `owner` written is the repository's own configured identity. When the repository has
  none, creation is refused, saying which setting is missing.
- [AC-8] Creating something that already exists, or that would land outside the project, is refused
  with what failed and why, and nothing is written.
- [AC-9] Creation can be started from the file tree itself, against the directory the user pointed at,
  without typing a path from the root of the project to get there.
