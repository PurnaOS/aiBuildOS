# RQ-0005 — Files and record artifacts are edited inside the workspace

[RQ-0004](rq-0004.md) makes the workspace a place to watch an agent work and to read the code and the
record. Reading is half of it. A person driving an agent corrects a line it got wrong, and — because
this project is requirement-first — writes the requirement *before* asking for the feature at all. If
neither can be done here, the workspace is a viewer and the real work happens somewhere else.

Editing a source file is ordinary. Editing an artifact is not, and this is the requirement
[DC-0009](../decisions/dc-0009.md) was waiting for when it deferred CST-based editing: `docs/` is the
system of record, it is committed, and **a writer that reformats frontmatter it never touched destroys
the diff**. The diff is how a human reviews what an agent changed, so preserving it is not tidiness —
it is the property that keeps the record reviewable.

An artifact is also not free text. It has a type, a state vocabulary, links with legal targets, and
acceptance criteria whose numbers are append-only ([OKF conventions](../guidelines/okf-conventions.md)).
Profile-driven validation — the engine reading the dialect that declares all of that — is being built
in parallel; this requirement is what puts it in front of a person, so that authoring an artifact by
hand and authoring it here produce the same bytes.

Two things stay out: creating artifacts through a wizard that allocates IDs and scaffolds links, and
any write to Git itself. Both are named in [EP-0004](../epics/ep-0004.md).

## Acceptance criteria

- [AC-1] A file opened from the workspace can be edited and saved, and the file on disk afterwards is
  exactly what was shown, byte for byte.
- [AC-2] An edited file that has not been saved is marked as such, and closing it asks first.
- [AC-3] When the agent changes a file that is open and unmodified, the view updates to match the file
  on disk and says that it did.
- [AC-4] When the agent changes a file that is open with unsaved edits, neither version is discarded.
  The user is told and chooses which to keep, and can see the difference before choosing.
- [AC-5] An artifact is edited as its own shape — its fields, its body and its acceptance criteria —
  and not as raw text.
- [AC-6] The states offered for an artifact are that type's own vocabulary, and the artifacts offered
  for a link are those its type declares as legal targets.
- [AC-7] Acceptance criterion numbers are append-only: adding one appends, and removing one retires
  its number without renumbering the rest.
- [AC-8] Saving an artifact rewrites only what changed. Fields, comments, ordering and formatting that
  were not edited are byte-identical afterwards.
- [AC-9] An artifact that would be invalid is reported against the field that caused it, at the point
  of editing, using the same rules the bundle validator applies.
- [AC-10] Saving an artifact keeps its directory index consistent with it.
- [AC-11] A file or artifact that cannot be written — no permission, removed underneath, unreadable —
  reports what failed and why, and does not lose the user's work.
