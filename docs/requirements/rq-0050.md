# RQ-0050 — Supervision reaches the harness

Supervision ([RQ-0022](rq-0022.md)) is honest about the application but silent toward the agent:
the harness runs at whatever permission posture it woke up with, however closely the owner asked to
supervise. Harnesses advertise their own permission behaviour as session config options — the
surface [RQ-0042](rq-0042.md) already reads and displays. Choosing a supervision level should set
the matching option too, so "review every step" and "let it run" are true on *both* sides of the
ACP wire. The mapping is per-harness data in the agent descriptor, not a hardcoded table
([DC-0028](../decisions/dc-0028.md) fixes the mechanism: standard config options, not the
deprecated session-modes API).

## Acceptance criteria

- [AC-1] Choosing a supervision level sets the harness's matching permission config option for the
  session, when the descriptor maps one.
- [AC-2] The mapping lives in the agent descriptor — per harness, per option, as data. No harness
  is special-cased in code.
- [AC-3] When a harness advertises no mappable option, supervision behaves exactly as today, and
  the settings surface says so rather than implying depth that isn't there.
- [AC-4] When the harness changes the option from its side, the supervision display follows — the
  two surfaces never silently disagree.
