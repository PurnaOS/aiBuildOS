# RQ-0031 — A command in the transcript reads like a terminal

An executed command renders today as an icon, the word `execute`, and the agent's title for it —
the command itself never shown, the output arriving only when everything is over, clamped to a
strip with no way to see the rest. Meanwhile the wire carries all of it: the command in the call's
raw input, streamed output in the update events every good terminal UI is built on, the final
output in the result. The owner's ask, verbatim: refer other systems and build something great.
The systems worth referring to agree on the shape — the command line, live monospace output, an
exit told in words, long output folded behind its count, a duration.

## Acceptance criteria

- [AC-1] An execute card shows the command it runs, monospace, from the moment it starts.
- [AC-2] Output streams into the card live as the command runs, not only at the end.
- [AC-3] The outcome is words — succeeded, failed — beside how long it took.
- [AC-4] Output beyond a screenful folds behind "show all N lines"; nothing is silently cut.
- [AC-5] The files a call touched stay visible after its result arrives.
- [AC-6] A result the card cannot parse renders as the text it is, never as an empty card; a
  terminal-handle content block renders honestly rather than as nothing.
