# RQ-0016 — A question from the agent is a choice, not a paragraph

When the agent needs something decided, today it writes a paragraph and the user writes one back.
The vision doc's promise is different: a short, clear question with the options laid out — a card
to tap, with typing always available for the answer the options did not anticipate.

How the question travels is [DC-0020](../decisions/dc-0020.md)'s business, and deliberately not
this document's: these criteria describe what a person sees, so the mechanism can change under
them without the requirement moving. The one mechanism-shaped constraint worth stating is the
failure mode: structure the application cannot read must degrade to ordinary visible text —
worse formatting, never a lost question.

## Acceptance criteria

- [AC-1] A question the agent poses with discrete options renders as a card offering exactly
  those options, in the agent's own wording.
- [AC-2] Choosing an option sends the answer to the agent, and the transcript keeps both the
  question and the answer.
- [AC-3] Free text is always available beside the options, and answers the same question.
- [AC-4] An unanswered question does not block the conversation, and stays answerable until the
  conversation has moved on.
- [AC-5] Malformed structure from the agent renders as the text it is, never as an error.
