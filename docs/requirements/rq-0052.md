# RQ-0052 — Plans and verdicts arrive typed

The most load-bearing things an agent says — the plan proposed from picked requirements
([RQ-0014](rq-0014.md)), the outcome of a check run ([RQ-0019](rq-0019.md)) — arrive as prose the
application then scrapes. Harnesses can return output conforming to a caller-supplied schema;
carried over the ACP extension surface ([DC-0028](../decisions/dc-0028.md)), a plan or a verdict
becomes data the application validates instead of text it hopes it parsed. Where the harness
doesn't support it, the prose path remains — typed is an upgrade, never a gate.

## Acceptance criteria

- [AC-1] When the connected harness supports the extension, a proposed plan arrives conforming to
  a schema the application supplies, and is rejected back to the agent when it doesn't.
- [AC-2] Check and verdict outcomes likewise arrive typed where supported.
- [AC-3] The channel is the ACP extension surface per [DC-0028](../decisions/dc-0028.md). No
  second door to the agent opens for this.
- [AC-4] On a harness without the extension, today's text flow continues unchanged, and the stub
  agent exercises both paths in CI.
