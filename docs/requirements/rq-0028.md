# RQ-0028 — A project carries instructions any agent reads

A real coding agent looks for its instructions at the project root — `AGENTS.md`, `CLAUDE.md` —
and a freshly scaffolded project has neither, so the most capable harness arrives knowing nothing
about the record it is standing in. The vision doc promised the opposite: the rules written into
the project so even a tool outside this application follows them.

`AGENTS.md` carries the substance; `CLAUDE.md` is one import line pointing at it. The substance:
this repository is its own record; where the conventions live; requirement-first; the state
discipline as the owner decided it (work states only on the story being implemented, worktree
builds hands-off, scheduling and verdicts always the person's); the playbooks; `docs:check` as
the gate. Plain root files, no frontmatter — the validator has no opinion about them.

## Acceptance criteria

- [AC-1] A newly created project has root `AGENTS.md` and `CLAUDE.md`, with the content above.
- [AC-2] `CLAUDE.md` is an import of `AGENTS.md`, not a second copy that can drift.
- [AC-3] The seed action that adds the standard playbooks to an adopted project seeds these too,
  and never overwrites either file where one exists.
- [AC-4] This repository's own root carries the same `AGENTS.md`, kept consistent with its
  `CLAUDE.md`.
