# RQ-0003 — The knowledge engine validates the bundle against the type profile

[`docs/profile/`](../profile/README.md) declares this project's SDLC schema as data: required fields,
state vocabularies, link targets with cardinality and cycle constraints, and required body sections.
[OKF conventions §6](../guidelines/okf-conventions.md#6-the-profile--types-are-data) states the
consequence plainly — *"editing a profile changes what is enforced; nothing about the types is
compiled in."*

That is not true yet. The validator hardcodes the common frontmatter and ships four rules, and reads
nothing from `docs/profile/` at all. So today a Story can omit `implements`, carry a state no
vocabulary contains, lose its acceptance criteria section, or name a TestCase as its `parent`, and
`bun run docs:check` reports no errors. The profile is documentation pretending to be a schema.

This requirement makes the profile the input to validation. It is the **rule registry** that
[DC-0009](../decisions/dc-0009.md) reserves — *"a rule/graph engine sits on top: artifacts form a
directed graph, and rules are evaluated over it to produce findings"* — and it stays inside the
knowledge engine, which [AR-0002](../architecture/ar-0002.md) makes the only code that parses `docs/`.

Permissive consumption is not negotiable here. OKF is *"permissively consumable — a reader tolerates
unknown types, unknown fields, and broken links rather than rejecting the bundle"*
([§1](../guidelines/okf-conventions.md#1-what-okf-is)). A validator is a stricter reader than a
consumer, but it still may not treat a type the profile has not described yet as a failure: `AR` is
ID-reserved and deliberately unprofiled, and that is a documented decision rather than an omission.

Enforcing *transitions* between states is out of scope. The profile declares `from → to` pairs, but a
validator sees one commit and cannot know what a state was before it; the same is true of the
append-only rule for `[AC-n]` numbers. Both need history and both get their own requirement. Gates,
CST-based editing and the Ajv `json_schema` escape hatch stay reserved by DC-0009.

## Acceptance criteria

- [AC-1] The type profile is read from the bundle's `profile/` directory as data. A type definition
  resolves its `extends` chain by merging fields, links and states by key with the child winning, so
  a type inherits its parent's constraints without restating them.
- [AC-2] An artifact whose `type` has no type definition is reported at warning severity, never as an
  error, and is still checked against the common frontmatter rules.
- [AC-3] An artifact declaring a type marked `abstract` is an error.
- [AC-4] An artifact's ID prefix and containing directory must be the ones its type declares.
- [AC-5] Fields a type declares `required` must be present, and a field constrained by `values:` must
  hold one of them.
- [AC-6] An artifact's `state` must appear in its type's state vocabulary.
- [AC-7] An artifact with `provenance: agent` must carry `generated`.
- [AC-8] A relationship the artifact's type does not declare is reported at warning severity.
- [AC-9] A link's target must have a type the relationship declares, accepting any type that extends
  one of them. A target type the profile does not define is matched by name, so a link to an
  unprofiled type is not a failure.
- [AC-10] `min` and `max` on a relationship are enforced. `min` does not apply while an artifact is
  in its type's initial state, so a draft may be incomplete.
- [AC-11] A relationship declared `cycles: forbid` reports a cycle once, naming the path around it.
- [AC-12] Body sections a type declares `required` must be present, and a section marked `items: AC`
  must carry at least one `[AC-n]` item with numbers unique within the artifact.
- [AC-13] A link to a single criterion (`RQ-0007#AC-2`) must resolve to a criterion that exists in
  the artifact it names.
- [AC-14] `bun run docs:check` reports every finding with its rule name, severity, file and — where
  the finding belongs to a frontmatter key — its line, and exits non-zero when any finding is
  error-severity. A bundle with no profile is validated against the common rules alone rather than
  refused.
