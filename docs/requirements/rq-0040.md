# RQ-0040 — Every session says what it is

Once builds, background runs and the chat all live in one registry, the inventory has to tell them
apart or the dock cannot. `session:list` rows gain `label: string|null` and `startedAt: ISO`. A
session's kind is **derived, never stored**: `storyId` set means build, `label` set means task,
neither means chat. Storing a kind alongside the fields it derives from would be a second source
of truth waiting to drift.

The case that makes the fields earn their place: a background run under `closest` supervision hits
a permission ask with nobody watching its tab. The dock renders the blocked ask; this requirement
makes the inventory data sufficient for it to do so.

## Acceptance criteria

- [AC-1] Every `session:list` row carries `label` (`string|null`) and `startedAt` (ISO-8601) —
  builds, background runs and the main chat alike.
- [AC-2] Kind is derived from the fields — `storyId` → build, `label` → task, neither → chat — and
  no stored kind field exists anywhere.
- [AC-3] A background session blocked on a `closest` permission is discoverable: the data in
  `session:list` is sufficient for the dock to render the blocked ask.
