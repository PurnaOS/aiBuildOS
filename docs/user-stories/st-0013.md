# ST-0013 — Edit a file beside the conversation

*As someone driving an agent, I want to fix a line myself without leaving the workspace, so that
correcting one character does not mean switching to another application and losing my place.*

Serves [RQ-0005](../requirements/rq-0005.md) criteria AC-1 to AC-4 and AC-11.

The case worth designing rather than discovering is the collision: the agent edits a file that is
open. If the copy on screen is untouched it reloads and says so. If it has unsaved edits **neither
version is discarded** — the difference is shown and the person chooses. Silently overwriting either
side is the one outcome nobody can defend.

A path arriving from the renderer is not trusted, which is why AC-11's containment is verified
directly against the boundary rather than through the interface ([TC-0023](../testing/tc-0023.md)).

## Acceptance criteria

- [AC-1] A file opens in the centre as a tab and saves back byte for byte.
- [AC-2] Unsaved edits are marked, and closing the tab asks first.
- [AC-3] An agent's change to an unmodified open file is taken, and said out loud.
- [AC-4] An agent's change to a file with unsaved edits keeps both until the person chooses.
- [AC-5] A save that fails says what failed and leaves the work in the editor.
