# ST-0004 — Open a project from the launch page

*As someone returning to aiBuildOS, I want to see the projects I have already added and open one, so
I can carry on where I left off.*

Serves [RQ-0002](../requirements/rq-0002.md) criteria AC-2, AC-9 and AC-10. Creating and adopting are
[ST-0003](st-0003.md); what opening then shows is [ST-0005](st-0005.md).

The launch page is what the application opens on when no project is open. It has no sidebar: a
project-scoped navigation with no project open would be describing something that does not exist.

Which project is open is renderer state ([DC-0005](../decisions/dc-0005.md)) — the list itself and
everything in it is owned by the main process and read across IPC at the point of use, never mirrored.

## Acceptance criteria

- [AC-1] With no project open, the application shows the launch page listing every registered
  project with its name, path, branch and when it was last opened.
- [AC-2] An empty registry shows a single line explaining what a project is and the two ways to add
  one. It is not an error, and it is not a wall of illustration.
- [AC-3] Each row shows whether its working tree has uncommitted changes, by text as well as by
  colour.
- [AC-4] Opening a project replaces the launch page with the project view and records that the
  project was opened.
- [AC-5] A project whose directory is missing is listed as unavailable with its path and can be
  forgotten from the row. The rest of the list keeps working.
- [AC-6] Closing a project returns to the launch page without restarting the application.
- [AC-7] The whole row is one focusable control, reachable and operable from the keyboard.
