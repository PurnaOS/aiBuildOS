# ST-0006 — Load the type profile

*As the knowledge engine, I want the type definitions in `docs/profile/` as resolved data, so the
rules that follow are driven by the profile instead of by what I was compiled with.*

Serves [RQ-0003](../requirements/rq-0003.md) criteria AC-1 and AC-14. The rules that consume this are
[ST-0007](st-0007.md) and [ST-0008](st-0008.md).

Two pieces that are deliberately separate. Reading files is impure and lives in `load.ts`, behind the
`@aibuildos/knowledge-engine/load` subpath, so importing the engine's pure parts stays free of
`node:fs` — the same boundary [ST-0005](st-0005.md) drew for `loadBundle`. Resolving `extends` is
pure and lives in `profile.ts`, which is what makes it testable from a literal rather than a fixture
directory.

`extends` merges by key with the child winning
([conventions §6](../guidelines/okf-conventions.md#6-the-profile--types-are-data)), which is how
`Story` inherits `depends_on` and `priority` from `WorkItem` without restating them, and how
`target: [WorkItem]` comes to accept a Story.

## Acceptance criteria

- [AC-1] The profile loads from the bundle's `profile/` directory. Files that are not type
  definitions — the index and the manifest, neither of which carries `type: TypeDefinition` — are
  skipped rather than reported.
- [AC-2] A type definition that will not parse, or whose dialect is malformed, is reported as a
  finding. It never throws and never takes the rest of the profile down with it.
- [AC-3] Resolving `extends` merges `fields`, `links` and `states` by key, child winning, along the
  whole chain rather than one level of it.
- [AC-4] A type is answerable about its supertypes, so a caller can ask whether `Story` is a
  `WorkItem` without knowing the chain.
- [AC-5] A type name the profile does not define answers that question by name equality rather than
  by failing, so an unprofiled type is never mistaken for a mismatched one.
- [AC-6] `bun run docs:check` loads the profile, reports profile findings alongside bundle findings,
  and keeps its existing output shape, `bundle/empty` guard and exit code.
- [AC-7] Validation with no profile at all runs the common rules and reports nothing about types — a
  newly created project is a valid bundle before it is a populated one.

## Notes

The profile is data, so the fixtures for [ST-0007](st-0007.md) and [ST-0008](st-0008.md) build type
definitions inline rather than reading this repository's own. A rule test that depends on
`docs/profile/story.md` is a test that fails when the profile legitimately changes.
