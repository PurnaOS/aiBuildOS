# ST-0051 — PR status through the optional gh

*As someone who has pushed a branch, I want its pull request's number and state in the sync
header, so that "what is the PR doing" stops needing a browser tab.*

Implements [RQ-0034](../requirements/rq-0034.md) on the mechanism
[DC-0024](../decisions/dc-0024.md) settles: new `main/pr.ts` runs
`execFile("gh", ["pr", "view", "--json", …])` — argv-only, the user's own authentication, no
token stored — behind a `project:pr-status` channel, on demand only. ENOENT maps to
`{ok: false, code: "gh_missing"}` as data; the `AIBUILDOS_GH_BIN` seam lets tests substitute a
stub binary. The surface is a PR chip in the sync header.

## Acceptance criteria

- [AC-1] With `gh` present and a PR open, `project:pr-status` answers with the PR's number and
  state and the chip shows both.
- [AC-2] With `gh` absent, the answer is `gh_missing` data; the chip stays quiet and no error
  surfaces.
- [AC-3] Status is fetched only on request — no polling loop, no timer.
