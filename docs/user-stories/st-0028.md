# ST-0028 — A story is built by the agent and accepted by a person

*As the person the work is for, I want to hand a ready story to the agent and get back a screen
holding what I asked for and what changed, side by side, so that accepting is a comparison and
not an act of faith.*

Serves [RQ-0015](../requirements/rq-0015.md).

"Build" on a ready story's card walks it `ready → queued → building` through the guarded save
and sends the build playbook with the story and its requirement as context. The end of the turn
flips it to `review` and offers the review surface: the story's criteria on one side, the
working tree's diffs on the other — both read from machinery that already exists (the criteria
module, the Git changes channel, the diff view). Accept flips `review → accepted`; send back
returns it to `building`, appends the note to the story, and sends the note to the agent. Git is
never written.

## Acceptance criteria

- [AC-1] A ready story's card offers Build; starting flips the states and sends the build
  playbook with story and requirement as context.
- [AC-2] Turn end flips `building → review`; the review surface shows criteria and working-tree
  diffs together.
- [AC-3] Accept and send-back are single acts: the flip, and for send-back the note appended to
  the story and prompted to the agent.
- [AC-4] The walk survives restart at every step, from the record alone.
