# ST-0005 — See a project's Git and record status

*As someone who has just opened a project, I want to see where its repository stands and what its
record contains, so I know what I am looking at before I ask an agent to change it.*

Serves [RQ-0002](../requirements/rq-0002.md) criteria AC-7, AC-8 and AC-11. Getting there is
[ST-0004](st-0004.md).

Two independent readings of the same directory, and either can be absent without the other failing: a
project may be a repository with no bundle, or — briefly, while Git is missing from the machine — a
bundle the app cannot read a branch for.

The record summary is counts only. The renderer never sees frontmatter: parsing `docs/` belongs to
the knowledge engine alone (AR-0002), and the walker that does it is shared with the `docs:check`
CLI rather than written twice.

## Acceptance criteria

- [AC-1] The project view reports the current branch, or that HEAD is detached.
- [AC-2] It reports working-tree state as counts of staged, unstaged and untracked paths, and says so
  in one line when the tree is clean.
- [AC-3] It lists the most recent commits with abbreviated hash, subject and date.
- [AC-4] A repository with no commits yet reports that, rather than failing to read a log.
- [AC-5] It summarises the OKF bundle as artifact counts by type and by state.
- [AC-6] A project with no `docs/` directory says so. A bundle with no artifacts reports zero
  artifacts, which is a valid state and not an error.
- [AC-7] Git being absent or the directory not being a repository is reported in the view with what
  failed, leaving the record summary still readable.
- [AC-8] Refreshing re-reads both without reopening the project.
