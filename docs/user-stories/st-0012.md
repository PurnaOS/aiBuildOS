# ST-0012 — The record rail and the files rail

*As someone about to ask an agent for something, I want the project's requirements and its files
beside the conversation, so I can point at what I mean instead of describing it.*

Serves [RQ-0004](../requirements/rq-0004.md) criteria AC-14, AC-15 and AC-16.

The record rail is the one that makes this aiBuildOS rather than a generic agent front end. It shows
what a requirement is implemented and verified by, and it does that by **deriving** the reverse of
stored links — never by reading a backlink someone wrote down, because a written backlink is a second
source of truth that drifts.

The files rail carries the working tree and, on a second tab, the same tree as Git sees it.

## Acceptance criteria

- [AC-1] The record rail groups artifacts by type and shows each one's ID, title and state.
- [AC-2] Expanding a requirement shows the work that implements it and the tests that verify it,
  derived from links stored in one direction only.
- [AC-3] Selecting an artifact opens it in the centre.
- [AC-4] A story can be attached to the conversation as context together with its acceptance criteria.
- [AC-5] The file tree reads a directory's children when it is expanded, never the whole tree at once.
- [AC-6] A path Git reports as changed is marked as changed, and an ignored path is not listed.
- [AC-7] The Git tab groups changes into staged, unstaged and untracked, and lists recent commits.
- [AC-8] Selecting a change opens its diff in the centre.
- [AC-9] A project with no record says so, and a bundle with no artifacts is not reported as an error.
