# ST-0054 — A surviving worktree can be picked up

*As someone whose build outlived its session, I want to resume it in its own worktree, so that a
quit or a crash costs me nothing the checkpoints already hold.*

Implements [RQ-0036](../requirements/rq-0036.md), closing the gap
[DC-0021](../decisions/dc-0021.md) named: a shared `attach()` is extracted from `startBuild` —
session start, the onTurnEnd checkpoint-then-flip, `live.set` — and `build:resume
{projectId, storyId, harnessId}` reuses it against a worktree located by branch alone, both name
forms. Refusals are `not_found`, `already_attached`, and the shared cap; a story at `review`
walks back to `building` via `applyArtifactEdit` before the fresh session prompts from the
checkpoints.

## Acceptance criteria

- [AC-1] `build:resume` attaches a fresh session in the surviving worktree — located by branch
  under either name form — and prompts it from the checkpoints.
- [AC-2] Resume refuses `not_found` with no matching worktree, `already_attached` with a session
  already there, and the cap refusal at three busy builds.
- [AC-3] A resumed story at `review` walks to `building`; checkpoints and the turn-end flip then
  behave exactly as in a fresh build, through the same `attach()`.
- [AC-4] Resume works after an application relaunch, consulting no session state.
