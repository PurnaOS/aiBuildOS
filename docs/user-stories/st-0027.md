# ST-0027 — A plan is draft artifacts, and approving it is a state change

*As someone who picked what to build, I want the agent's proposal to arrive as reviewable
draft stories and tests I can shape and then approve in one act, so that saying go is mine and
the plan is never anywhere but the record.*

Serves [RQ-0014](../requirements/rq-0014.md).

Picking is checkboxes on the Backlog board's ready column, feeding the plan playbook
([ST-0026](st-0026.md)) with the picked IDs as context. The Plan tab is a derived view — every
Story and TestCase at `draft`, grouped by the requirement it implements, ordered by dependency
then ID — that exists whenever draft work does, offered from a banner on the Backlog. Approving
walks the drafts through the guarded save one at a time: stories to `ready`, test cases to
`active`. A story with no verifying test fails its flip and wears the refusal; the rest proceed.

## Acceptance criteria

- [AC-1] Ready requirements can be picked on the Backlog and the plan playbook started with
  exactly those as context.
- [AC-2] The Plan tab derives from the record: all draft stories and test cases, grouped by
  requirement, in dependency order; it is reachable whenever draft work exists and holds no
  state of its own.
- [AC-3] Drafts open in the ordinary editor from the plan, and can be retired from it.
- [AC-4] Approve flips each story `draft → ready` and each test case `draft → active` through
  the guarded save; a story that fails its flip shows the refusal on its row while the rest
  proceed.
