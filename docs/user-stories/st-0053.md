# ST-0053 — Sprint stories build in parallel

*As someone running a sprint, I want its stories building side by side off the sprint branch and
merging back onto it, so that the batch integrates on its own branch before main ever moves.*

Implements the build half of [RQ-0035](../requirements/rq-0035.md) on
[ST-0052](st-0052.md)'s lifecycle: `branchFor(storyId, sprintId?)` names sprint builds
`aibuildos/sp-NNNN--st-NNNN` — the `--` binding, since git's ref namespace forbids `/` nesting
under a branch name — extending [DC-0021](../decisions/dc-0021.md)'s no-tracked-file recovery.
`startBuild` gains an optional `sprintId` (base = the sprint branch; `no_sprint` when its
worktree is missing), and `mergeBuild`/`reviewBase` route to the sprint worktree when the branch
names one. Record flips stay in the main checkout, so the sprint branch's `docs/` never drifts
from base and the boards never lie about sprint stories.

## Acceptance criteria

- [AC-1] A story built with a `sprintId` builds on `aibuildos/sp-NNNN--st-NNNN`, branched from
  the sprint branch; a missing sprint worktree refuses with `no_sprint`.
- [AC-2] The accepted merge of a sprint story lands on the sprint branch in the sprint's
  worktree — never on main — and review diffs read against the sprint branch.
- [AC-3] State flips for sprint stories happen in the main checkout only; the sprint branch's
  `docs/` stays byte-identical to its base until the sprint merges.
- [AC-4] Two sprint stories build in parallel worktrees off the same sprint branch and both
  merges land on it.
