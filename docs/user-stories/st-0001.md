# ST-0001 — Configure harnesses in settings

*As someone opening aiBuildOS for the first time, I want to be asked to attach a coding harness, and
to manage that list afterwards, so the app has an agent to drive.*

Serves [RQ-0001](../requirements/rq-0001.md) criteria AC-1 through AC-4. The connection itself is
[ST-0002](st-0002.md).

The first-run prompt carries no persisted state: the renderer asks for the harness list, and an empty
list *is* the first run. There is no flag to get out of sync with reality.

## Acceptance criteria

- [AC-1] Harnesses persist as JSON under the application's user-data directory. The file path is a
  parameter of the store, so it is testable without Electron and overridable for end-to-end runs.
- [AC-2] A missing, unreadable or malformed harness file yields an empty list rather than a crash.
- [AC-3] Saving a harness without an ID creates one; saving with an ID replaces that record.
- [AC-4] The settings view lists every harness with its command, and offers edit and remove on each.
- [AC-5] The add form offers the shipped presets, prefilling command and arguments; the user can edit
  every field before saving.
- [AC-6] Launching with an empty harness list opens the attach dialog. Launching with at least one
  harness does not.

## Notes

Renderer state stays UI-only ([DC-0005](../decisions/dc-0005.md)) — the harness list is owned by the
main process and read across IPC at the point of use, never mirrored into the store.
