# ST-0032 — Finished work is committed from the workspace

*As the person who just accepted a story, I want to land its changes without leaving, as my own
Git would land them, so that history is mine and hooks still mean something.*

Serves [RQ-0018](../requirements/rq-0018.md). `git.ts` gains its first writes — stage, unstage,
commit, argv only, errors carried verbatim — and the Git tab gains the controls: a stage/unstage
affordance per change row, a message field, a commit button. Accepting a story
([ST-0028](st-0028.md)) offers the commit with a message derived from the story — its ID and its
title; declining changes nothing. Hook output is the interesting path: a rejection's stderr is
the message shown, because the hook already said it better than a paraphrase would.

## Acceptance criteria

- [AC-1] Change rows stage and unstage from the Git tab, and the counts follow.
- [AC-2] A commit with a message lands, appears in the tab's history, and runs the user's hooks —
  a rejection shows the hook's own words and leaves the work staged.
- [AC-3] Accepting a story offers a commit whose message names the story; declining leaves the
  tree untouched.
- [AC-4] Nothing in a playbook or an agent's reach triggers a commit.
