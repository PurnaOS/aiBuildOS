# ST-0039 — The running application appears beside its review

*As the person deciding whether it's done, I want to click through the running thing next to what
was asked for, so that the verdict is about the product and not the diff.*

Serves [RQ-0025](../requirements/rq-0025.md) by DC-0012's mechanism with RQ-0019's declaration
style: a playbook's fenced run block carries the command and the URL it serves; main spawns the
server (stdlib child_process — DC-0012 named execa before the checks runner proved the stdlib
suffices), waits for the URL to answer, and a WebContentsView renders it beside the review.
Closing the review kills the server; before-quit kills whatever is left.

## Acceptance criteria

- [AC-1] A run fence in an active playbook makes Preview available on a story's review; no fence,
  no Preview.
- [AC-2] Preview starts the declared command, waits for its URL, and renders it inside the
  workspace, isolated from the application's own session.
- [AC-3] A server that fails to start or answer reports why in its own words; closing the review
  stops it; quitting the application orphans nothing.
