# ST-0060 — The agent popover

*As someone steering an agent, I want one place that answers "how is this agent set up right
now?", so that mode, options and supervision stop being three separate hunts.*

Implements [RQ-0042](../requirements/rq-0042.md): `Controls.tsx` becomes `AgentPopover.tsx`, one
Radix popover grouped by **origin** — Session for the ACP session mode, the harness's
`displayName` verbatim for its own options, Supervision merged in. Origin is the disambiguator
because two options can legitimately share a name; the popover never renames, dedupes, or guesses.

## Acceptance criteria

- [AC-1] One popover holds the ACP session mode, the harness's options, and supervision, grouped
  by origin with the harness's `displayName` verbatim as its group heading.
- [AC-2] Two options sharing a name render both, distinct through their groups — neither renamed,
  deduped, nor dropped.
- [AC-3] Supervision works inside the popover as it did on its own and keeps
  `data-testid="supervision"`.
- [AC-4] While supervision is `hands-off`, the closed popover's trigger shows an amber echo.
