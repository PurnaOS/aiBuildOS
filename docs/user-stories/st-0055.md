# ST-0055 — Every build row says where it works

*As someone glancing at the dock, I want each build row to say which branch and worktree it
works in and what can still be done with it, so that a worktree is never invisible machinery.*

Implements [RQ-0037](../requirements/rq-0037.md): `BuildRow` gains `path`, `sprintId`, `ahead`
(`rev-list --count base..HEAD`) and `lastCheckpointAt` (`log -1 --format=%aI`), and the
`build:list` response gains `sprints: [{sprintId, branch, path, dirty, stories}]` so sprint
worktrees are reported alongside story ones. The dock's build rows render branch, a sprint chip
where one applies, the dirty/orphaned/resumable distinction, and a Resume action riding
[RQ-0036](../requirements/rq-0036.md)'s channel.

## Acceptance criteria

- [AC-1] A build row names its branch and worktree path, and carries a sprint chip when the
  build belongs to a sprint.
- [AC-2] A row shows commits ahead of its base and its last checkpoint time; no checkpoints yet
  reads as words, not a blank.
- [AC-3] Dirty, orphaned and resumable rows are visibly distinct, and a resumable row's Resume
  action starts a resume.
- [AC-4] `build:list` reports live sprint worktrees — sprint id, branch, path, dirty state, and
  the stories building off them.
