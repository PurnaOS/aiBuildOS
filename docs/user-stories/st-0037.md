# ST-0037 — A build takes a worktree, and accepting it is the merge

*As someone who wants to keep working while the agent builds, I want the build in its own
worktree and its landing to be my accept, so that parallel is safe and history is mine.*

Serves [RQ-0020](../requirements/rq-0020.md) exactly as [DC-0021](../decisions/dc-0021.md)
settles it: branch-as-binding, process state in main only, checkpoint commits on the branch,
accept = the --no-ff merge, restart = reconciliation. git.ts grows the worktree verbs; the
session registry runs the build session with the worktree as cwd; the review surface reads the
branch's changes; conflicts are Git's words, left for a person.

## Acceptance criteria

- [AC-1] Build-in-worktree walks the story's states in main, spawns the session in a fresh
  worktree on `aibuildos/<story>`, and the main workspace stays usable throughout.
- [AC-2] Turn ends checkpoint a dirty worktree on its branch; hook rejections surface as data.
- [AC-3] Review shows the branch's changes; accept merges --no-ff, removes the worktree, deletes
  the branch; a conflict is reported verbatim and discarding is equally explicit.
- [AC-4] Reopening the project lists surviving worktrees, and a fresh session can pick one up.
