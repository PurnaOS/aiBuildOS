# ST-0030 — A question is a card, and an answer is a tap

*As someone the agent needs an answer from, I want its question as options I can tap, so that
answering takes a second and typing stays my escape hatch.*

Serves [RQ-0016](../requirements/rq-0016.md), by [DC-0020](../decisions/dc-0020.md)'s convention:
a custom assistant-message component (CopilotKit's own `AssistantMessage` seam) detects the
` ```aibuildos-question ` fence on a **completed** message, renders the surrounding prose as
usual, and puts a card where the fence was — the agent's wording, the agent's options, a tap
sending the answer through the ordinary prompt path. While the message still streams, and for any
fence that does not parse, the text renders as text.

## Acceptance criteria

- [AC-1] A completed message carrying a well-formed question fence renders it as a card; the
  message's other prose renders as it always did.
- [AC-2] Tapping an option sends its answer as an ordinary visible prompt; the card shows what
  was chosen.
- [AC-3] The composer keeps working beside the card, and a typed reply answers the same question.
- [AC-4] A fence that does not parse, or arrives mid-stream, renders as plain text.
