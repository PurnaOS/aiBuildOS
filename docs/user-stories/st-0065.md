# ST-0065 — A kill reaches the whole process tree

*As someone closing the app mid-check or stopping a preview, I want the process actually gone —
on every OS — not just the shell that launched it.*

Fixes [BG-0009](../bugs/bg-0009.md). One shared reaper in `apps/desktop/src/main/reap.ts`:

- Checks and previews spawn with `detached` on POSIX, so the child leads its own process group;
  killing signals the group (`process.kill(-pid, "SIGTERM")`), which takes dash's wrapper and
  the real work together. Windows walks the tree with `taskkill /pid <pid> /T /F`.
- A fallback direct `child.kill()` covers a spawn that raced its own death.
- The ACP reap tests stop wrapping `pgrep -f` in `sh -c` (Linux's pgrep matches the wrapper's
  own command line) and skip on Windows, where `/bin/sh` does not exist.

The terminal work ([RQ-0038](../requirements/rq-0038.md), [DC-0026](../decisions/dc-0026.md))
inherits this: a PTY retires the same ceiling natively for user shells, while `reap.ts` covers
every shell-spawned runner.

## Acceptance criteria

- [AC-1] Killing a running check ends the command's real process, not just its shell wrapper, on
  macOS, Linux and Windows; the run settles instead of waiting on held pipes.
- [AC-2] Stopping a preview (or `killPreviews` at quit) leaves the declared server dead and its
  port free on all three OSes.
- [AC-3] The ACP reap tests measure survivors with `pgrep` invoked directly, so a wrapper shell's
  command line can never report a survivor that never existed; on Windows they skip.
