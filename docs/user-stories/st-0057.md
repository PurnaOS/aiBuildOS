# ST-0057 — Background playbook runs

*As someone planning while work happens, I want a playbook to run beside the chat, so that a
long run never holds the conversation hostage.*

Implements [RQ-0039](../requirements/rq-0039.md): `session:start` gains `background: {label}`,
the registry stores the label on `Held`, and `busyCount()` becomes the one cap check shared with
worktree builds. The renderer reuses `compose()` and fire-and-forgets `session:prompt` — the
WorkBoard worktree-prompt precedent — while the main chat and its CopilotKit pipeline stay
untouched. Turn-end needs no wiring: the watcher sees whatever the run writes.

## Acceptance criteria

- [AC-1] A playbook started in the background runs to completion while the main chat keeps
  answering.
- [AC-2] Background runs and worktree builds spend from the same cap of three, through one
  `busyCount()`.
- [AC-3] What the run writes reaches the workspace through the watcher, with no turn-end wiring
  added for background sessions.
