# ST-0025 — The validator's findings stand beside the work

*As someone about to approve work an agent drafted, I want anything the validator would refuse
marked where I am already looking, so that CI is a backstop and not a discovery.*

Serves [RQ-0012](../requirements/rq-0012.md).

The record read the workspace already performs gains the findings the engine already computes —
the same `validate` run `docs:check` does, carried per artifact over the existing record channel
rather than a new one if the shape allows. The record rail and the boards mark affected
artifacts in words ("2 errors", not a red dot); the artifact editor already places findings
beside their fields. A clean record adds nothing anywhere.

## Acceptance criteria

- [AC-1] Where artifacts are listed, ones with findings carry a mark in words, errors told apart
  from warnings.
- [AC-2] The marks re-derive with the record on every refresh, whoever changed the files.
- [AC-3] A clean record shows no trace of the machinery.
