# ST-0003 — Create or adopt a project

*As someone starting work in aiBuildOS, I want to point it at a codebase — a new one it creates for
me, or one I already have — so the product has a subject.*

Serves [RQ-0002](../requirements/rq-0002.md) criteria AC-1, AC-3 through AC-6, AC-9 and AC-11 through
AC-12. Listing and opening are [ST-0004](st-0004.md).

Both flows begin at the same native directory picker, and the picker is its own IPC channel rather
than a step inside creating: the user has to see the location before naming anything, and a cancelled
picker is not a failed creation.

Git is the system `git` binary invoked with an argv array ([DC-0010](../decisions/dc-0010.md)) — the
user's own config, hooks, credential helpers and signing all apply, which is the point and also why
creating a project can fail for reasons that belong to their machine rather than to this app.

## Acceptance criteria

- [AC-1] Projects persist as JSON under the application's user-data directory. The file path is a
  parameter of the store, so it is testable without Electron and overridable for end-to-end runs.
- [AC-2] A missing or unreadable projects file yields an empty list; a file that exists but cannot be
  read as project configuration refuses to be written over rather than silently replacing it.
- [AC-3] Creating a project refuses a target directory that already exists, and reports that as a
  distinct outcome rather than writing into it.
- [AC-4] A project name is a directory name, not a path: separators, traversal and characters the
  filesystem rejects are refused before anything is written.
- [AC-5] A created project is a Git repository with exactly one commit, containing a README and a
  seeded OKF bundle.
- [AC-6] Adopting a directory that is already inside a Git repository does not initialise a second
  repository inside it.
- [AC-7] Adopting a directory that is already registered yields the existing project, and the list
  does not grow.
- [AC-8] Git being absent, and Git having no configured `user.name`/`user.email`, are reported as
  distinct, explained outcomes rather than as thrown errors.
- [AC-9] Forgetting a project removes only its registry entry.

## Notes

Expected failures cross IPC as data, not as exceptions — the same choice
[ST-0002](st-0002.md) made for the ACP probe. Electron rewraps a thrown handler error as
"Error invoking remote method …", which is not a sentence to show anyone.

Creating a project is not rolled back when the commit fails: the directory and its bundle are real,
and deleting a tree the app may not have created cleanly is worse than leaving it.
