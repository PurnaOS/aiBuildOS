# ST-0059 — No inert affordances

*As someone using the workspace, I want everything that looks pressable to press and every label
to say what its press does, so that the chrome never advertises behaviour it does not have.*

The zero-breakage slice of [RQ-0041](../requirements/rq-0041.md), sequenced first for exactly that
reason: nothing here moves a surface, so nothing here can collide with the redesign lanes. The
rail's inbound links become the buttons they already look like (`onOpen` is in Row's props today),
PlanTab's `window.confirm` becomes the established Radix dialog idiom, the two dead props go, and
the four ambiguous labels start saying which action is which.

## Acceptance criteria

- [AC-1] Pressing an inbound link in the rail opens the linked artifact; PlanTab's retire prompt
  is the application's own Radix dialog, and no `window.confirm` remains in the renderer.
- [AC-2] `NowTab.onPrompt` and `ReviewTab.onOpen` are deleted — nothing passed them, so no caller
  changes.
- [AC-3] The commit buttons read "Commit staged" and "Commit all changes"; the review's sends read
  "Send back to build session" and "Hand to main chat"; FileTab's held dot carries its tooltip.
