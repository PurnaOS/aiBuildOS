# ST-0026 — The standard steps are buttons the project carries

*As someone who should not have to know what to type at an agent, I want the standard steps as
labelled buttons whose exact words I can inspect, so that pressing one is something I can trust
without being able to write it.*

Serves [RQ-0013](../requirements/rq-0013.md), the way [DC-0019](../decisions/dc-0019.md)
decided: a `Playbook` type in the profile, the standard set seeded by the scaffold template, the
buttons a filtered view of the record. Composition is string work in the renderer — playbook
body plus a context line naming each selected artifact — and the send is the ordinary prompt
path, so the transcript shows the user's own message saying exactly what was sent. The ⓘ
popover shows the same text before it is sent, with the harness's display name.

## Acceptance criteria

- [AC-1] The profile in the scaffold template declares `Playbook`, and new projects arrive with
  the standard set as active playbook artifacts.
- [AC-2] The workspace shows a button per active playbook, from the record alone; a project
  without playbooks shows none and offers to seed the standard set.
- [AC-3] Pressing composes body plus selected context and sends it as an ordinary visible
  prompt; the ⓘ shows the same text and the harness before pressing.
- [AC-4] A playbook edited or minted like any artifact changes its button with no application
  change; `harness` matches by display name and falls back to the attached harness.
