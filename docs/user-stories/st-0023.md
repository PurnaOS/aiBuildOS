# ST-0023 — A state moves only along its type's paths

*As someone whose record is about to be written by boards, agents and buttons, I want the
application's own door to refuse an illegal state change, so that what the record says happened
could actually have happened.*

Serves [RQ-0010](../requirements/rq-0010.md).

The engine grows one honest helper — legal transitions for a type from a state, read from the
profile — and the artifact save path uses it: it already reads the file before writing, so the
previous state is in its hand. The artifact editor's state control stops offering the whole
vocabulary and offers what the helper allows. Criteria get the same treatment: a save that
renumbers or reuses an existing `[AC-n]` is refused, because every `#AC-n` reference ever written
points at that number.

Anything that arrives from outside the application is displayed exactly as found.

## Acceptance criteria

- [AC-1] The engine answers "which states may follow this one" from the profile's transitions,
  wildcard retirement included.
- [AC-2] The artifact save path refuses an undeclared pair and a criteria renumbering, each in
  words naming what was refused.
- [AC-3] The editor's state control offers exactly the legal next states, and the index row's
  state cell follows a legal flip in the same write.
- [AC-4] A state or criterion written outside the application is shown as found.
