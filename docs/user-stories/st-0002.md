# ST-0002 — Test a harness over ACP

*As someone who has just configured a harness, I want to press Test and see the agent answer, so I
know the configuration is right before trusting it with my repository.*

Serves [RQ-0001](../requirements/rq-0001.md) criteria AC-5 through AC-8. Depends on
[ST-0001](st-0001.md) for the harness record.

The client is the official ACP TypeScript SDK ([DC-0007](../decisions/dc-0007.md)) and lives entirely
in the main process — the renderer never holds a child process or a model client.

## Acceptance criteria

- [AC-1] The probe spawns the harness with piped stdio, exchanges newline-delimited JSON-RPC over
  stdin/stdout, and declares no filesystem or terminal client capabilities.
- [AC-2] A permission request from the agent during a test is declined rather than surfaced — a probe
  must not modify the user's machine.
- [AC-3] A successful probe returns the negotiated protocol version, the agent's advertised
  identity, capabilities and authentication methods, the session ID, the reply text and the stop
  reason.
- [AC-4] A failed probe returns the stage that failed — spawn, initialize, session or prompt — a
  stable error code, a message, and whatever the agent wrote to stderr.
- [AC-5] An agent answering `session/new` with an authentication-required error is reported as its
  own outcome, listing the authentication methods, and is not presented as a broken harness.
- [AC-6] The probe is bounded by a timeout and terminates the whole process group on every path, so
  an agent launched through `npx` dies with its launcher.
- [AC-7] Automated coverage runs against `tools/stub-acp-agent`; no test calls a live model.
- [AC-8] A working directory that does not exist is reported as such. It raises the same `ENOENT` as
  a missing command, so it is ruled out before the spawn rather than told apart afterwards.
