# ST-0033 — The project's checks run from the workspace

*As the person deciding whether a story is done, I want the project's own checks run and their
verdict beside the story, so that accepting is evidence and not optimism.*

Serves [RQ-0019](../requirements/rq-0019.md). The checks live in a playbook — fenced ` ```check `
command blocks in an ordinary record artifact, seeded as `PB-0004 "Run the checks"` — which a
person reads, an agent follows, and main runs: each command a `child_process` spawn (stdlib, no
new dependency), streamed output over an event, exit code the verdict, every child dead when the
application exits. The engine parses the artifact; main only extracts the fences from the body it
is handed. The review surface shows the latest run beside the story and offers a failing run to
the agent as one button.

## Acceptance criteria

- [AC-1] Checks are the fenced commands of a checks playbook, listed from the record; no playbook,
  no checks offered.
- [AC-2] Running them streams each command's output as it arrives and reports pass, fail, or
  could-not-run per command, in words, by exit code alone.
- [AC-3] The review surface shows the latest run's outcome and hands a failure to the agent in
  one act, failure text included.
- [AC-4] Quitting the application leaves no check process behind.
