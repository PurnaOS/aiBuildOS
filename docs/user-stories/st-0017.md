# ST-0017 — Start a file, and mint an artifact

*As someone starting a piece of work, I want to write the requirement here rather than discovering it
here, so the workspace is where the record is kept and not only where it is amended.*

Serves [RQ-0006](../requirements/rq-0006.md).

Two affordances, deliberately different. The files rail creates a **file** — a path and nothing else.
The record rail mints an **artifact** — which means allocating a number that is never reused, writing
what the type requires, and adding the index row that makes the bundle valid the moment the file
exists.

The number is the high-water mark of what the bundle already has, plus one. A number belonging to an
artifact that was deleted is not recovered: nothing but git history records it, and inventing a place
to record it is a field the profile does not have.

## Acceptance criteria

- [AC-1] The files rail offers creating a file, at a path the user gives, relative to the project.
- [AC-2] The record rail offers minting an artifact of any type the profile declares and permits.
- [AC-3] A minted artifact carries its type's required fields, its declared body sections, and an ID
  no artifact in the bundle has used.
- [AC-4] Its index row is written with it.
- [AC-5] It opens in the centre as soon as it exists.
- [AC-6] A refusal says what failed — the path is taken, the identity is missing, the profile has no
  such type — and writes nothing.
