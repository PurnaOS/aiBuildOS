# ST-0041 — A build's flip belongs to its own project

*As someone who switches projects while a build runs, I want the finished build to move its own
story wherever I am, so that the record never depends on what happens to be on my screen.*

Fixes [BG-0007](../bugs/bg-0007.md). The `building → review` flip moves from the Now tab into
main: `builds.ts`'s turn-end hook — which already checkpoints — performs the guarded edit against
the session's own project path, through the same transition-checked core the artifact-save
handler uses, extracted once rather than duplicated. Main announces the change; windows refresh;
the Now tab keeps only its view.

## Acceptance criteria

- [AC-1] The flip runs in main against the build's own project, with no window state involved —
  switched away, launch page, or closed record tab alike.
- [AC-2] The guarded-edit core is one function shared by the save handler and the flip, not two
  copies of the transition check.
- [AC-3] The Now tab performs no record writes.
