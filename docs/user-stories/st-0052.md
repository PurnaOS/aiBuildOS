# ST-0052 — A sprint is a branch with a worktree

*As someone batching related stories, I want to start, finish or discard a sprint as one
deliberate act, so that the batch has a shape and main only moves when I say so.*

Implements the Sprint record and lifecycle of [RQ-0035](../requirements/rq-0035.md) as
[DC-0025](../decisions/dc-0025.md) settles it: the profile grows a `Sprint` type (`SP`,
`docs/sprints/`), and `sprint:start/merge/discard` channels drive `startSprint`, `mergeSprint`
and `discardSprint` in `builds.ts`. Starting mints the artifact with `contains: [ST-…]`, creates
`aibuildos/sp-NNNN` and adds its worktree — merging into an un-checked-out branch is impossible,
so the worktree is the mechanism, not a convenience. Finish merges `--no-ff` into main; finish
and discard both refuse `stories_live` while any `sp-NNNN--*` worktree survives. The Work header
gains the sprint selector, the create-from-ready-checkboxes action, a progress count and Finish.
Sprint-aware story builds are ST-0053's half of the requirement.

## Acceptance criteria

- [AC-1] Starting a sprint from checked ready stories mints `SP-NNNN` with `contains: [ST-…]`,
  creates branch `aibuildos/sp-NNNN` and adds a worktree checked out on it.
- [AC-2] Finishing merges the sprint branch into main with `--no-ff`; finish and discard refuse
  with `stories_live` while any `sp-NNNN--*` worktree lives.
- [AC-3] The Work header offers the sprint selector as a filter, "Start a sprint with N
  stories" over the ready checkboxes, a progress count and Finish.
- [AC-4] A sprint survives an application restart with no tracked file — its branch and worktree
  are the whole record.
