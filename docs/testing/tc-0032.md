# TC-0032 — The chosen appearance is in force, and survives a restart

Verifies [RQ-0007](../requirements/rq-0007.md) AC-1 to AC-6.

Asserted through the media query rather than through a stored value, because the media query is what
every stylesheet in the application actually reads. A setting written to disk that the window does not
reflect is the failure this is here to catch.

## Steps

1. Start with no configuration. Expect the appearance to be following the system.
2. Choose dark. Expect the window to report a dark preferred colour scheme immediately, and a surface
   drawn on the dark ground.
3. Choose light. Expect the reverse, again without reopening anything.
4. Expect no class or attribute on the document recording the choice — the renderer reads the media
   query and holds no second answer.
5. Choose to follow the system. Expect no override in place at the platform — following the system is
   a statement about deferring to it, not about any one colour, and asserting a colour here would only
   restate whatever the desktop running the test happens to be set to.
6. Restart the application. Expect the chosen appearance to be in force on the first frame — asserted
   on the platform's own value, because a border proves nothing on a machine whose desktop is already
   dark.
7. Read a settings file that is absent, empty, malformed, or names an appearance that does not exist.
   Expect the system default each time, and the unreadable file left as it was.
8. Tell an absent settings file apart from one that cannot be used, so the second can be reported.
9. Save an appearance that is not one of the three. Expect a refusal.
