# TC-0095 — Resume rides the shared attach and refuses right

Verifies [RQ-0036](../requirements/rq-0036.md) AC-1, AC-2 and AC-3 at the unit level: the
`attach()` extracted from `startBuild` serving both paths, the three refusals, and the
`review → building` walk — against a fixture repo and a fake session, no application running.

## Steps

1. Resume a story whose worktree survives under `aibuildos/st-NNNN`, then under
   `aibuildos/sp-NNNN--st-NNNN`. Expect both located by branch alone and attached through the
   same `attach()` a started build uses — session start, the onTurnEnd checkpoint-then-flip,
   `live.set` — prompted from the worktree's checkpoints.
2. Resume a story with no matching worktree. Expect `not_found`.
3. Resume a story whose worktree already holds a live session. Expect `already_attached`.
4. With three builds busy, resume a fourth. Expect the shared cap refusal.
5. Resume a story sitting at `review`. Expect it walked back to `building` via
   `applyArtifactEdit`, then checkpoints and the turn-end flip behaving exactly as in a fresh
   build.
