# TC-0023 — A path from the renderer never reaches outside the project

Verifies [RQ-0005](../requirements/rq-0005.md) AC-11 and [RQ-0004](../requirements/rq-0004.md)#AC-18.

The renderer is not trusted; that is the whole reason the IPC boundary exists
([AR-0001](../architecture/ar-0001.md)). This case drives that boundary directly rather than through
the interface, because the interface is not what an attack would use.

It exists because the file channels shipped with an unvalidated path, which was an arbitrary read
**and an arbitrary write** anywhere on disk. Nothing could reach it without a renderer-side flaw
first — but an arbitrary write behind an IPC channel is precisely what such a flaw would escalate
through, and the boundary's job is to be the thing that does not depend on the renderer behaving.

## Steps

1. Open a project containing an ordinary file, and a symlink pointing at a directory outside it.
2. Ask to read a path that climbs out with `..`. Expect a refusal.
3. Ask to read an absolute path. Expect a refusal.
4. Ask to write to a path that climbs out. Expect a refusal.
5. Ask to write **through the symlink** — a path with no `..` in it that nonetheless lands outside.
   Expect a refusal: this is the one a string check cannot catch, and it is why the path is resolved
   and compared as well as inspected.
6. Ask to list a directory through that symlink. Expect a refusal.
7. Read an ordinary file inside the project. Expect it to work — the point is containment, not
   refusing everything.
8. Expect no file to exist anywhere outside the project afterwards.
