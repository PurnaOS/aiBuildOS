# TC-0007 — Git reads branch, working-tree counts and commits, and names its own failures

Verifies [RQ-0002](../requirements/rq-0002.md) AC-5, AC-7 and AC-11. Runs on Node under Vitest
against the real `git` binary in a temporary repository.

Step 6 exists because it is the most likely parsing bug in the whole feature: porcelain v2 emits a
*second* NUL-terminated field for a renamed path, and a reader that does not consume it miscounts
every entry after the first rename.

## Steps

1. In an empty temporary directory, expect the repository root to be reported as absent.
2. Initialise it. Expect the root to be the directory itself, and expect reading the log of a
   repository with no commits to return an empty list rather than an error.
3. Create a file and read status. Expect it counted as untracked, not as staged or unstaged.
4. Stage it. Expect it counted as staged. Commit, then expect a clean tree and one commit whose
   subject, abbreviated hash and date are all reported.
5. Modify the committed file. Expect it counted as unstaged.
6. Rename a committed file with `git mv` and read status. Expect the counts to be correct — one
   staged path, nothing spurious — proving the rename's extra record was consumed.
7. Create a subdirectory inside the repository and ask for its repository root. Expect the
   repository's root, not the subdirectory — this is what stops adopting a subfolder from
   initialising a nested repository inside an existing one.
8. Run a Git command in a directory that is not a repository. Expect a failure carrying Git's own
   message, distinguishable from Git being absent.
9. Attempt a commit with no `user.email` configured. Expect the identity failure to be reported as
   its own distinct outcome.
10. Configure `core.fsmonitor` in the repository to point at a program that leaves a marker file, then
    read the repository — status, log and repository root. Expect the marker **not** to exist: reads
    force that setting off, because `.git/config` travels with a directory and the launch page reads
    every registered project on every launch ([DC-0010](../decisions/dc-0010.md)).
