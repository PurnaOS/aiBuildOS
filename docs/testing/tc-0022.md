# TC-0022 — A file is edited and saved unchanged, and a collision with the agent loses nothing

Verifies [RQ-0005](../requirements/rq-0005.md) AC-1 through AC-4. Playwright against the built
application with the scripted stub ([DC-0013](../decisions/dc-0013.md)).

The third case is the one worth having. An agent editing a file the user is also editing is not a
rare race — it is the ordinary situation in this product — and the requirement it must satisfy is
that **neither version is lost**.

## Steps

1. Open a project and open a file from the file rail. Expect an editor.
2. Change it. Expect the tab and the editor both to say there is unsaved work.
3. Save. Expect the file on disk to be **exactly** what was shown — nothing appended, trimmed or
   normalised — and expect the unsaved marker to clear.
4. With the file open and unmodified, have the file change underneath and end a turn. Expect the
   editor to show the new contents, and expect no conflict to be raised: there was nothing of the
   user's to lose.
5. With unsaved edits in the file, have it change underneath and end a turn. Expect both versions to
   survive: the editor still holds the user's text, and the difference is shown beside it.
6. Move to the conversation and back before that happens. Expect the unsaved work to still be there —
   switching tabs must not discard an edit.
7. Take the agent's version. Expect the editor to hold it and the conflict to clear.
