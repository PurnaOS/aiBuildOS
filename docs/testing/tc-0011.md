# TC-0011 — Frontmatter rules check type, prefix, directory, fields, state and provenance

Verifies [RQ-0003](../requirements/rq-0003.md) AC-2 through AC-7, covering
[ST-0007](../user-stories/st-0007.md). Runs on Node under Vitest against artifacts and a profile
built as literals.

Severity is under test as much as detection: an unprofiled type must not be able to fail a build.

## Steps

1. Validate an artifact whose `type` has no definition. Expect exactly one finding, at **warning**
   severity, and expect the common frontmatter rules still to have run against it.
2. Validate an artifact declaring an `abstract` type. Expect an error.
3. Validate an artifact whose ID prefix is not its type's. Expect an error naming the expected prefix.
4. Validate an artifact sitting in a directory other than its type's. Expect an error naming the
   expected directory.
5. Omit a field the type declares `required`. Expect an error naming the field.
6. Set a field constrained by `values:` to something outside them. Expect an error naming what was
   allowed.
7. Set `state` to a value outside the type's vocabulary. Expect an error. Set it to a value that is in
   the vocabulary but not reachable by any declared transition, and expect **no** finding — membership
   is checked, transitions are not.
8. Set `provenance: agent` with no `generated`. Expect an error. Repeat with `provenance: human` and
   expect none.
9. Expect every finding to carry the line of the frontmatter key that caused it.
10. Validate an artifact that satisfies its type completely and expect no findings at all.
