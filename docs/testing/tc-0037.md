# TC-0037 — Collapsing the chrome leaves the panes as the user sized them

Verifies [RQ-0009](../requirements/rq-0009.md) AC-4.

One reading has to be written down. The pane layout is fractional
([TC-0035](tc-0035.md)'s restart comparison already leans on that), so when the sidebar's 224
pixels are reclaimed the panes *cannot* all keep their pixel widths — the sizes the user chose
**are** the fractions. "Stay sized" therefore means: the chosen proportions hold while the sidebar
is away, and the exact widths return when it is back. What must never happen is a toggle resetting
a drag to the defaults.

## Steps

1. Size a pane by dragging its separator, with the sidebar collapsed.
2. Restore the sidebar. Expect the pane's share of the workspace unchanged — the reclaimed width is
   shared in the proportions the user chose, not redistributed.
3. Collapse it again. Expect the pane at exactly the width the drag left it.
