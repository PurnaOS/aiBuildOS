# TC-0005 — Project registry persists, dedupes by path and refuses to overwrite a bad file

Verifies [RQ-0002](../requirements/rq-0002.md) AC-1, AC-9 and AC-12. Runs on Node under Vitest
against a temporary directory — the store takes its file path as a parameter, so no Electron runtime
is needed. The same shape as [TC-0001](tc-0001.md), for the same reason.

## Steps

1. Load projects from a path that does not exist. Expect an empty list, no throw.
2. Add a project. Expect a generated ID back and the record on disk.
3. Load again from the same path. Expect exactly that project, field for field.
4. Add the same path a second time. Expect the *existing* project back and a list of one, not two.
5. Add the same path with a trailing separator. Expect the same single record — paths are compared
   normalised, not as raw strings.
6. Add a second, different project. Expect two records.
7. Stamp the first as opened. Expect its `lastOpened` to change and nothing else to.
8. Remove the first by ID. Expect only the second to remain, and expect the directory the removed
   project pointed at to still exist on disk untouched.
9. Write `not json at all` into the file. Expect loading to yield an empty list, and expect adding to
   *throw* rather than replacing the file — reading a corrupt file as empty and then saving over it
   would erase every project in it.
