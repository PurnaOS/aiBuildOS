# TC-0072 — A rejected read at turn end still lands on screen

Verifies [BG-0006](../bugs/bg-0006.md) against [RQ-0015](../requirements/rq-0015.md): a failing
read or save at turn end propagates rather than vanishing into a swallowed rejection, and the
failure reaches where the workspace can say so.

[DC-0022](../decisions/dc-0022.md)'s watcher retired the turn-end bump this case once also
covered — refresh now rides the same `project:changed` event any write produces, not a signal
this path fires itself. What is left to prove is narrower and just as load-bearing: a rejection
is never caught and dropped.

## Steps

1. Drive `turnEndWalk` with a save that rejects. Expect the rejection to propagate out of
   `turnEndWalk` unswallowed — `useTurnEnd.ts` carries it onward as `onProblem`, which
   `Workspace.tsx` renders as the dismissible `turn-end-problem` bar above the tab strip.
2. Drive it with everything succeeding. Expect exactly the previous flip behaviour, byte for byte.
