# TC-0017 — Permission, authentication and session controls are the agent's, not ours

Verifies [RQ-0004](../requirements/rq-0004.md) AC-9, AC-10, AC-12 and AC-13, against the stub agent.

The point of this case is negative as much as positive: it fails if the application ever invents an
option the agent did not send.

## Steps

1. Have the stub request permission. Expect the request to be surfaced with exactly the options the
   stub sent, in the stub's own wording, and expect the turn to wait.
2. Answer it. Expect the answer to reach the stub and the turn to continue.
3. Request permission again and cancel the turn instead of answering. Expect the request to be
   answered as cancelled.
4. Have the stub refuse to open a session until authenticated. Expect a named authentication outcome
   carrying the methods the stub advertised, distinguishable from a crash and from a missing command.
5. Have the stub advertise modes and configuration options. Expect them to be reported as offered.
6. Change one. Expect the stub to be told, and expect the reported value to follow the stub's own
   confirmation rather than the request.
7. Have the stub advertise none. Expect nothing to be reported as offered — not an empty set of
   choices.
8. Have the stub advertise a configuration category the protocol does not name. Expect it to survive
   with the stub's own label.
9. Have the stub advertise commands. Expect them to be reported.
