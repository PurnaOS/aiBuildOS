# TC-0107 — The popover groups by origin and never dedupes

Verifies [RQ-0042](../requirements/rq-0042.md) AC-1 and AC-2 at the component level: one popover
carries every agent setting, grouped by origin, and a name collision between origins survives
untouched — origin disambiguates, so nothing is renamed, deduped, or guessed at.

## Steps

The grouping is a pure module (`agentControls.ts`) beside the component that draws it — the same
split `playbooks.ts` keeps from its strip, and the reason this case needs no renderer harness
([AR-0002](../architecture/ar-0002.md): the bundle carries no jsdom).

1. Group an ACP session mode, a harness's own options, and supervision. Expect three groups:
   Session holding the session mode, the harness's `displayName` verbatim heading its options,
   and supervision in the same set.
2. Feed two options that share a name, one from the session mode and one from the harness. Expect
   both kept under their own group headings — neither renamed, merged, nor dropped.
3. Group a set with no agent-advertised options. Expect that group omitted rather than rendered
   empty — absent is not the same as offering nothing (RQ-0004#AC-12's rule, kept here).
