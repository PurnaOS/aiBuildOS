# TC-0087 — Branch enumeration and ahead/behind parse clean

Verifies [RQ-0033](../requirements/rq-0033.md) AC-2 and AC-3 at the unit level: the `branches`
verb's `for-each-ref` parse (`%1f` separators) and the `# branch.ab` line the existing
porcelain-v2 `changes()` now reads. The nullability is the point: no upstream is `null`, never
rendered-as-zero's raw material.

## Steps

1. In a fixture repo with several branches — one with an upstream and commits either side, one
   in sync, one with no upstream — call `branches`. Expect one enumeration naming every local
   branch with its upstream and ahead/behind counts.
2. Expect the no-upstream branch's counts to be `null`, distinct from the in-sync branch's
   `0/0`.
3. Parse porcelain-v2 output carrying `# branch.ab +2 -1`. Expect ahead 2, behind 1 on the
   current branch's status.
4. Parse porcelain-v2 output with no `# branch.ab` line. Expect `null` counts, not zeros.
