# TC-0016 — Every ACP session update maps onto AG-UI events

Verifies [RQ-0004](../requirements/rq-0004.md) AC-5 through AC-8. A pure function over recorded
updates, so it needs neither a process nor a window.

This is the case that stops the bridge from quietly dropping an update kind the way the probe does
today — the bridge is where [DC-0008](../decisions/dc-0008.md)'s promise that the renderer sees only
AG-UI either holds or fails.

## Steps

1. Feed one update of **every** kind the protocol defines through the bridge. Expect each to produce
   events, and expect no kind to be silently dropped.
2. Feed two message chunks sharing an identifier. Expect one message, opened once and closed once.
3. Feed a chunk with a different identifier. Expect a second message to begin.
4. Feed reasoning chunks. Expect them to be distinguishable from message text.
5. Feed a tool call, then an update carrying new content and locations. Expect the content and the
   locations to be **replaced**, not appended to.
6. Feed a tool call carrying a diff. Expect the path, the old text and the new text to survive.
7. Feed a plan, then a second plan. Expect the second to replace the first entirely.
8. Feed each stop reason. Expect an ordinary end to differ from a refusal and from a cancellation.
9. Expect nothing the bridge emits to carry the agent's own wire vocabulary.
