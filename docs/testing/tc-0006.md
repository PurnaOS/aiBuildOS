# TC-0006 — A created project is a repository with one commit and a valid empty OKF bundle

Verifies [RQ-0002](../requirements/rq-0002.md) AC-3 and AC-4. Runs on Node under Vitest in a
temporary directory, against the real `git` binary — the point of
[DC-0010](../decisions/dc-0010.md) is that there is no second implementation to test against.

The bundle assertion runs the knowledge engine's `validate` over the seeded bundle. That is what makes
it impossible to ship a seed that is not a valid OKF bundle: a broken template fails this test rather
than every project a user creates.

## Steps

1. Scaffold a project into a fresh temporary directory, with a Git identity configured locally for
   the test.
2. Expect the directory to be a Git repository whose root is the project directory itself.
3. Expect exactly one commit, and expect it to contain the README and every seeded file.
4. Expect `docs/profile/` to hold all ten type-definition files and `docs/` to hold an index for
   every artifact directory.
5. Load the seeded bundle with the knowledge engine and validate it. Expect **no error-severity
   findings**.
6. Expect the summary to report zero Requirements, Epics, Stories, TestCases and Bugs — an empty
   backlog is the correct state for a new project, not a defect — but exactly three `Playbook`
   artifacts, the standard set (RQ-0013#AC-1), each carrying the identity the seeding commit itself
   carries rather than the template's own `{{OWNER}}` token.
7. Scaffold into a directory that already exists. Expect a refusal identifying the path as existing,
   and expect the existing directory's contents to be untouched.
8. Scaffold with a name containing a path separator, and with `..`. Expect both refused before
   anything is written.
