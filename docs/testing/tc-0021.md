# TC-0021 — Session controls come from the agent, and follow the agent when it changes them

Verifies [RQ-0004](../requirements/rq-0004.md) AC-12 and AC-13. Playwright against the built
application with the scripted stub ([DC-0013](../decisions/dc-0013.md)).

The second case is the point of the first: this fails if the application ever shows a control the
agent did not offer, or shows a value the agent has not confirmed.

## Steps

1. Open a project and start a session with an agent that advertises modes, a model, an effort level
   and a command.
2. Expect a control for each, showing the value the agent said it is currently set to.
3. Change the model. Expect the agent to be told, and expect the control to show the new value only
   because the agent confirmed it.
4. Change the mode. Expect the same.
5. Choose an advertised command. Expect it to be sent, and expect the conversation to show what was
   sent — a command that reached the agent without appearing in the conversation would be a message
   the user cannot see.
6. Start a session with an agent that advertises none of these. Expect **no controls at all** —
   absent, rather than empty menus or disabled dropdowns.
