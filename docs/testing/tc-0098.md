# TC-0098 — The dock's build rows say where and what next

Verifies [RQ-0037](../requirements/rq-0037.md) AC-1 and AC-3 through the running application:
the dock's build rows naming branch and sprint, telling dirty, orphaned and resumable apart,
and a Resume that actually resumes.

## Steps

1. Build a story inside a sprint. Expect its dock row naming the `aibuildos/sp-NNNN--st-NNNN`
   branch and carrying the sprint's chip; a plain build's row names its branch with no chip.
2. Dirty one worktree from outside. Expect its row visibly marked dirty, distinct from its
   neighbours.
3. Relaunch the application so a build's session dies. Expect that row marked resumable —
   distinct from dirty — and offering Resume.
4. Press Resume. Expect the row live again with a stub session attached in the same worktree,
   riding [RQ-0036](../requirements/rq-0036.md)'s channel.
