# BG-0010 — A directory index can disagree with the artifact it lists, and nothing says so

The validator checks that every artifact is *listed* in its directory index
([`index/listed`](../requirements/rq-0003.md)), but not that what the index *says* about it is
true. An index row carries the artifact's state, and that state can drift from the artifact's own
frontmatter with `docs:check` reporting zero errors.

Found while walking EP-0016's record: a shell brace that did not expand left
`docs/requirements/rq-0049.md` at `state: building` while its row in
`docs/requirements/README.md` had already moved to `verified`. Two full `docs:check` runs passed
in between — 305 artifacts, 0 errors — and the disagreement was caught only by reading the
artifacts directly.

This matters more than a typo would. [OKF conventions §8](../guidelines/okf-conventions.md#8-index-files)
makes the index navigation *derived from* the artifacts, and
[the record is the system of record](../decisions/dc-0015.md): a board or a report generated from
the index would state a different truth than the file it points at, with nothing flagging the
split. The same class of drift is possible for a row's title and its links.

## Reproduction

1. Edit any artifact's `state:` in its own file — say `docs/requirements/rq-0001.md` from
   `verified` to `draft`.
2. Leave its row in `docs/requirements/README.md` reading `verified`.
3. Run `bun run docs:check`. It reports 0 errors.

## What a fix would need

A rule alongside `index/listed` — call it `index/agrees` — comparing each index row's stated state
(and, if cheaply parseable, its title) against the artifact's frontmatter, reported at error
severity like the other index rule. The row format is already fixed enough to parse: the ID link
is what `index/listed` matches on today.

Worth deciding at the same time: whether indexes should be *generated* rather than hand-maintained,
which would remove the drift instead of detecting it — a bigger change, and one that touches how
every artifact is authored.
