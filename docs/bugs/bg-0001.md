# BG-0001 — The rails keep showing the record and the tree as they were when the project opened

Both rails read once, when they mount, and never again. Ask the agent to write a requirement and the
record rail still says *No artifacts yet — the first requirement goes here* while the file it wrote
sits in `docs/requirements/`. The file tree only looks current because it expands lazily: a folder
opened after the fact is read fresh, and one already open is not.

This is [RQ-0004](../requirements/rq-0004.md)#AC-14 and #AC-15 not being met. A panel that lists a
snapshot from before the work is not listing the project's record; it is listing the record the
project used to have, with nothing on screen admitting the difference.

The same staleness follows the user's own editing: saving a state change in an artifact tab leaves
the rail showing the old state.

## Reproduction

1. Open a project whose `docs/` bundle has no artifacts.
2. Ask the agent to write a requirement, and let the turn finish.
3. The file appears in `docs/requirements/`, and the record rail still reports no artifacts.
4. Open an artifact, change its state, save. The rail still shows the state it had before.
