# DC-0018 — Renderer libraries for the workspace, chosen against the Content-Security-Policy

## Context

[DC-0004](dc-0004.md) settled React, Vite, Tailwind and Radix. Until now the renderer has needed one
Radix package and nothing else. The workspace needs considerably more — a conversation, markdown, code
with highlighting, diffs, a code editor, resizable panels — and those are the kinds of libraries most
likely to break in this particular application, because the renderer runs under

    default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'

That forbids code generated from strings and blocks every remote origin. It is already why this
project configures Zod with `jitless` ([DC-0006](dc-0006.md)). Choosing these libraries on popularity
rather than against that policy is how a desktop application ends up loosening its own CSP.

## Decision

Adopt the following, each chosen for compatibility with that policy first:

| Need | Choice |
| --- | --- |
| Conversation | `@copilotkit/react-core`, `@copilotkit/react-ui` — required by [DC-0008](dc-0008.md), used with agent instances rather than a runtime URL |
| Event vocabulary | `@ag-ui/client`, `@ag-ui/core`, `rxjs` — `@ag-ui/core` is imported by main too, for the bridge |
| Markdown | `react-markdown` with `remark-gfm` |
| Code highlighting | a JavaScript highlighter, **not** `shiki` |
| Diffs | `diff`, to build hunks from the old and new text a tool call reports |
| Code editing | CodeMirror 6 |
| Panels | `react-resizable-panels` |
| Icons | `lucide-react` |

**No web fonts.** `default-src 'self'` has no font exception, so type comes from system stacks or
locally bundled files. Personality comes from how type is set, not from what is downloaded.

**Nothing is added before it is proven under the CSP.** That spike has now been run, end to end, in
the built application. Its results are recorded below because they are the evidence this decision
rests on.

## What the spike measured

A custom `AbstractAgent` streaming a canned turn into `CopilotChat`, in the built Electron app under
`default-src 'self'; script-src 'self'`:

- **It works.** The stream rendered progressively, with **zero console errors** and no
  Content-Security-Policy violation. No HTTP runtime, no localhost port, no CSP change.
- **The Zod risk did not materialise.** `@ag-ui/*` depends on Zod **3**, which is interpreted; the
  `new Function` compilation that forced `jitless` on this project is a Zod **4** behaviour, so the
  second copy is harmless.
- **`selfManagedAgents` is a paid-tier feature.** Using it logs: *"part of CopilotKit's Enterprise
  Intelligence offering. Provide a `publicLicenseKey` for production use."* It is a `console.warn`
  inside a `useEffect` — nothing is gated in code — but it is an explicit commercial position on the
  one mechanism that lets this application avoid running a server.
- **The renderer goes from 696 KB to 23 MB**, across 367 chunks. `@copilotkit/react-ui` brings
  `mermaid`, `cytoscape` and a syntax highlighter carrying every language grammar.

Both of the last two were put to the project owner with the alternatives — keeping AG-UI as the
vocabulary while writing the transcript by hand would have avoided both — and the decision was to
**keep CopilotKit in full**. This decision therefore stands as written, with the cost known rather
than discovered.

## Consequences

- The renderer's dependency count goes from one to roughly nine, and its build output grows by a
  factor of thirty. That is the measured cost of DC-0008 plus in-app editing, accepted deliberately.
- `@copilotkit/react-ui` already carries `react-markdown`, `remark-gfm` and a syntax highlighter, so
  those are **not** added separately — the markdown and highlighting rows above are satisfied by it.
- Packaged application size and cold start become worth watching, which they were not before.
- `shiki` is excluded because its default engine is WebAssembly, which would require `wasm-unsafe-eval`
  in the CSP. A highlighter is not worth widening the policy for.
- Monaco is excluded for CodeMirror: Monaco expects web workers and a loader, and is far heavier for an
  editor that opens one file at a time.
- Every one of these ships in the Electron bundle, so bundle size becomes a thing worth watching for
  the first time.
- If the spike fails, this decision and DC-0008 are revisited together, because the conversation
  library is the load-bearing one.

## Alternatives considered

- **Writing the conversation, markdown rendering and editor by hand.** It would keep the dependency
  count at one and is not obviously mad given the renderer only draws an append-only list — but it
  contradicts DC-0008, which is accepted.
- **`shiki` with the JavaScript engine**, avoiding WebAssembly. Kept as the fallback if a plain
  highlighter proves inadequate; it is not the default because the WASM path is.
- **Loading fonts from a CDN.** Requires a CSP change for decoration, which is the wrong trade in a
  desktop application.
