# DC-0007 — Agent integration through the official ACP TypeScript SDK

## Context

aiBuildOS drives coding agents. Integrating each vendor's bespoke interface would make every new agent
a bespoke port, and would couple the product to whichever vendor was integrated first.

## Decision

Speak **ACP (Agent Client Protocol)** using the **official TypeScript SDK**,
`@agentclientprotocol/sdk`. Agents are **stdio child processes**: aiBuildOS spawns the agent binary
and exchanges JSON-RPC over its stdin/stdout.

**ACP is the only door to AI.** No component reaches a model by any other route — no direct vendor
SDK calls, no HTTP clients to model providers.

Tier-1 agents at bootstrap:

| Agent | Command |
| --- | --- |
| Claude Code | `npx -y @agentclientprotocol/claude-agent-acp` |
| Codex | `npx -y @agentclientprotocol/codex-acp` |
| Gemini CLI | `npx -y @google/gemini-cli --acp` |

These are the commands that exist today, verified against npm: the `@zed-industries/*` adapters were
renamed to `@agentclientprotocol/*`, and Gemini's `--experimental-acp` is deprecated in favour of
`--acp`. `pi` was listed here at bootstrap and is dropped — it has no ACP mode. The list ships as
editable presets ([RQ-0001](../requirements/rq-0001.md)#AC-3), so a stale entry is a config edit, not
a release.

An agent adapter is configuration, not code: a name, a command, and its arguments.

## Consequences

- Adding a Tier-1 agent is a config entry, not an integration project.
- Permissions, secrets, and filesystem access all funnel through one protocol surface that can be
  brokered and audited in one place.
- Testing never needs a live model: a scripted stub agent speaks the same protocol
  ([DC-0013](dc-0013.md)).
- The client landed with [RQ-0001](../requirements/rq-0001.md): `packages/acp` spawns agents and runs
  the round trip, and `@aibuildos/acp/probe` is the only module in the repo that imports
  `node:child_process` for an agent.

## Alternatives considered

- **Per-vendor SDKs**: N integrations, N auth models, N failure modes.
- **MCP as the primary integration**: solves tool exposure, not agent-session driving. The two are
  complementary; ACP is the one that fits "run a coding agent".
