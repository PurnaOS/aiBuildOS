# DC-0013 — Vitest, Playwright and a scripted stub ACP agent

## Context

Three things need testing and they are not alike: pure TypeScript packages, the Electron application
as a running program, and the agent integration — which involves a model, a network, and a bill.

## Decision

- **Vitest** for unit and component tests, colocated as `*.test.ts` beside the source.
- **Playwright** for end-to-end tests, driving the **built** Electron app via `_electron.launch()`.
  No browser download is needed; a display server is (hence `xvfb-run` on Linux CI).
- **A scripted stub ACP agent** (`tools/stub-acp-agent`) — a real JSON-RPC/stdio binary that replays
  scripted responses.

**No live model is ever called in CI.** Agent behaviour is tested against the stub, which speaks the
same protocol as a real agent ([DC-0007](dc-0007.md)).

Tests run on **Node**, not Bun — see [DC-0002](dc-0002.md) for why and how.

## Consequences

- CI is deterministic, offline, free, and fast.
- The stub is production-shaped: it is spawned as a child process over stdio exactly like a real agent,
  so the spawn path itself is under test rather than mocked away.
- Playwright tests require a build first, which makes `build` a prerequisite step in CI.

## Alternatives considered

- **`bun test`**: fast, but it would run tests on a runtime the application never uses.
- **Mocking the ACP client**: tests the mock, not the protocol handling or the process boundary.
- **Recorded live-model fixtures**: brittle and expensive to refresh.
