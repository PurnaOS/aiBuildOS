# DC-0022 — A file watcher is the bump's source; the revision counter stays its mechanism

## Context

Freshness has been a revision counter bumped at the main session's turn end and on the
application's own writes. First real use showed what that model cannot see: everything a
terminal, another editor, a long-running agent turn, or Git itself does. The record is files —
a product whose screens are "a live look at those files" cannot be blind to the files changing.

## Decision

The main process watches an open project's root with **chokidar** — the boring, cross-platform
choice; `fs.watch` recursion is not portable to Linux and this is exactly the wheel not to
reinvent. Changes are debounced (~300ms) into one `project:changed` event; the renderer's answer
is the same `bump()` it already had — the counter remains the render mechanism, the watcher
becomes its one ambient source. `node_modules`, `.git/objects`, build output are ignored;
`.git/HEAD`, `.git/refs` and `.git/index` are deliberately included, so a commit made in a
terminal reaches the Git tab like any other fact.

The turn-end refresh bumps are removed rather than kept alongside — two sources for the same
signal is how the triple-refresh happened. Turn-end *walks* (state flips) keep their logic; the
watcher sees their writes like anyone else's. What the watcher makes hot, main cools: the record
read gains an mtime-generation cache, so ten bumps re-parse nothing that did not change.

## Consequences

- One new production dependency, in main only.
- Mid-turn agent writes, external edits and terminal Git all appear within a debounce, not a turn.
- The renderer keeps zero watcher knowledge; a window that misses events misses nothing durable —
  the next read tells the truth regardless.
- Worktrees are not watched in v1; their visibility remains the review surface and the Now row
  that names where the build works.
