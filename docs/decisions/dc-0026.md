# DC-0026 — The shell is a real PTY: node-pty in main, @xterm/xterm in the dock

## Context

[RQ-0038](../requirements/rq-0038.md) puts a shell in the workspace. The tempting build is the one
the app already knows: `child_process` plus a styled transcript. Two facts rule it out, and both
are load-bearing:

1. **The process-group kill ceiling.** Killing a spawned shell does not reliably kill its
   grandchildren — the dev server `npm` started survives the `npm` that started it. A PTY retires
   that ceiling: closing the controlling terminal delivers the hang-up to the foreground process
   group, which is exactly the job-control behaviour a real terminal has.
2. **Non-TTY children suppress prompts and colors.** Programs check `isatty` and, over a pipe,
   drop their colors, progress bars and interactive prompts. No amount of renderer styling brings
   back output the child never produced.

So: a real PTY. This is the app's first native module — accepted by the owner — and the choice of
packages has to survive Electron's ABI and bun's install behaviour.

## Decision

**node-pty** in the main process, **@xterm/xterm** (with the fit addon) rendering in the activity
dock.

- **Building for Electron's ABI: the root `postinstall` IS the build.** Bun blocks dependency
  lifecycle scripts, so node-pty's own install step never runs; relying on it would fail silently.
  The repository's own root `postinstall` — which bun does run — invokes `@electron/rebuild`, so a
  plain `bun install` leaves the binary correct for Electron.
- **Fallback:** `@homebridge/node-pty-prebuilt-multiarch`, if rebuilding across the 3-OS matrix
  proves flaky. Same API, prebuilt binaries.
- **Rejected:** `@lydell/node-pty` — no Electron-ABI prebuilds, which is the one problem a prebuilt
  fork would need to solve here.
- **Never top-level-import node-pty.** `terminals.ts` takes an injected pty-factory; the native
  module loads lazily inside main only. Vitest runs on Node ([AR-0001](../architecture/ar-0001.md))
  and must never load a binary built for Electron's ABI — unit tests exercise `terminals.ts`
  against a fake factory.

**Non-goal:** checks and previews keep their recorded ceilings. This decision is the user's
interactive shell, not a rework of how agent commands run; ACP `clientCapabilities.terminal`
stays parked in EP-0004.

## Consequences

- The app's first native module, and `postinstall` becomes a build step every checkout runs.
- The user's shell behaves like a shell: colors, prompts, resize, and a close that takes the whole
  job with it.
- Unit tests stay on Node untouched — the fake pty-factory keeps the native module out of vitest
  entirely.
- No terminal scrollback persistence in v1: a renderer reload reattaches to a blank view while the
  pty lives on. The upgrade path is a main-side ring buffer, when it earns its place.
