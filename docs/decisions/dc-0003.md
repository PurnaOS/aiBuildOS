# DC-0003 — Electron with electron-vite as the desktop shell

## Context

aiBuildOS is a desktop application: it drives local agent processes, reads and writes the user's Git
working trees, spawns development servers, and renders live previews. That set of capabilities rules
out a browser-only deployment.

## Decision

Ship as an **Electron** application, built with **electron-vite**, which gives main, preload, and
renderer three coordinated Vite builds from one config.

## Consequences

- Main and preload are bundled to CommonJS/ESM for Electron's Node; the renderer is a normal Vite
  React build. Three tsconfigs (`node` / `web`) keep typechecking honest across the split.
- The renderer never gets Node integration. Everything privileged crosses the typed IPC boundary
  ([DC-0006](dc-0006.md)).
- Electron's Node version, not the host's, is what main-process code must target — see
  [DC-0002](dc-0002.md).

## Alternatives considered

- **Tauri**: smaller binaries, but the ecosystem for the pieces this product needs (WebContentsView
  previews, `safeStorage`, mature auto-update) is Electron's, and the team's language is TypeScript
  end to end.
- **Web app + local daemon**: two distribution problems instead of one, and a worse story for
  filesystem and process access.
