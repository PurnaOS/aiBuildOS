# DC-0010 — System Git CLI driven by argv, with worktrees for isolation

## Context

Git is central: it is the storage layer for the record ([DC-0015](dc-0015.md)) and the mechanism by
which parallel agents work without colliding. The product must also behave identically to what the
user sees in their own terminal.

## Decision

Drive the **system `git` CLI**, invoking it with an **argv array** — never a shell string. Isolate
concurrent work in **`git worktree`s**: each agent stream gets its own working directory on its own
branch, sharing one object store.

## Consequences

- The user's Git version, config, hooks, credential helpers, and signing all apply. No reimplementation
  drifts from real Git behaviour.
- argv invocation removes shell-injection as a class of bug: branch names, paths, and messages are
  arguments, never interpolated text.
- Worktrees give parallel agents real filesystem isolation at the cost of disk, and merging becomes an
  explicit, reviewable step rather than an accident.
- Git must be present on the user's machine; the app checks for it at startup.

## Alternatives considered

- **`isomorphic-git` / `nodegit`**: no dependency on system Git, but a second implementation of Git
  semantics that will diverge, and no support for the user's hooks and credential helpers.
- **Shelling out with string commands**: injection risk for no gain.
