# DC-0005 — Zustand holds renderer UI state only

## Context

The renderer has two very different kinds of state: ephemeral view state (which pane is open, what is
selected, sidebar width) and domain state that lives in the main process behind IPC (the OKF graph,
agent sessions, Git status). Conflating them produces a store that is half cache, half UI, and stale
in ways nobody can reason about.

## Decision

**Zustand is for renderer UI state only.** One store, at
`apps/desktop/src/renderer/src/state/ui-store.ts`. Nothing outside `src/renderer` imports it.

Domain state is *not* mirrored into Zustand. It is requested across the typed IPC boundary
([DC-0006](dc-0006.md)) at the point of use, and the main process is its only owner.

## Consequences

- The store stays small and obviously correct; there is no cache-invalidation problem in the renderer.
- How domain reads are cached and revalidated is deliberately unsettled — the predecessor project used
  TanStack Query for this. That choice waits for the first feature requirement that needs it rather
  than being guessed at now.
- A second Zustand store is a smell, not a pattern. If one appears, the boundary above was crossed.

## Alternatives considered

- **Redux Toolkit**: more ceremony than this UI needs.
- **Zustand for everything including domain data**: rejected above — it makes the renderer a second
  source of truth for state the main process owns.
