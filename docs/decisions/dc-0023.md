# DC-0023 — Remote sync rides the user's own git

## Context

[RQ-0032](../requirements/rq-0032.md) brings fetch, pull and push into the workspace, which means
the application talks to remotes for the first time — and remotes mean credentials, divergence,
and the temptation to sync helpfully in the background. Each of those has a wrong answer that
costs the user's trust the first time it fires unasked.

## Decision

**Sync is the user's own git, one press per verb.** Fetch, pull and push run the system `git`
through the existing argv chokepoint ([DC-0010](dc-0010.md)); the user's credential helpers, SSH
agent, config and hooks all apply, and the application stores no credentials. Nothing is
automatic: no auto-push, no auto-fetch, no polling — every contact with a remote is a press.

**Pull is `--ff-only`.** A diverged branch is a decision for a person; the failure surfaces in
git's own words rather than the application choosing merge or rebase on their behalf. Push retries
once as `push -u origin <branch>` when the branch has no upstream, so publishing a new branch is
one press, not a riddle.

**Failures become codes.** `toGitError` gains regex-mapped `git_auth` and `no_remote` so the
interface can respond to the two common failures by kind, with stderr preserved alongside.

**Sync verbs take the plain-`git()` posture**, not DC-0010's read guard. That guard strips
`core.fsmonitor` from the application's own silent, repeated reads; a sync is a command a person
just pressed — exactly the class DC-0010 wants running under the user's full config, hooks and
credential helpers.

Freshness needs nothing new: the watcher already includes `.git/refs`, so a sync that moves refs
reaches the screens like any other change.

## Consequences

- Auth prompts, signing, and hook behaviour are exactly what the user's terminal would do; nothing
  to configure in the app and no drift from real git.
- No credential storage means no credential leaks — the application's threat surface does not grow.
- A user without a remote or without credentials gets a mapped, actionable failure, not a hang.

## Alternatives considered

- **Auto-fetch / auto-push in the background**: rejected. Ambient remote contact means ambient
  auth prompts and surprise pushes; every sync being its own press keeps the user the author of
  every remote effect.
- **Merge or rebase pulls**: rejected. Divergence handled silently is history rewritten or merged
  without a person deciding; `--ff-only` fails fast in git's words.
- **An embedded git implementation or stored tokens**: rejected. Reimplementing git's credential
  chain drifts from what the user's terminal does and makes the app a credential custodian for no
  benefit.
