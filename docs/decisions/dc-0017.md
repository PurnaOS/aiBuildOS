# DC-0017 — The ACP to AG-UI bridge runs in main; the renderer drives a custom AbstractAgent

## Context

[DC-0008](dc-0008.md) chose CopilotKit for the conversation and AG-UI as the event vocabulary, with
ACP events bridged into AG-UI so that "the renderer consumes AG-UI only". It settled the vocabulary and
deliberately left the mechanism to the requirement that needed it. [RQ-0004](../requirements/rq-0004.md)
is that requirement, and three facts about this application decide the mechanism.

**CopilotKit normally expects an HTTP runtime.** Its runtime is a request handler mounted in an app
server — Next.js, Express, Hono. An Electron application has no such server, and standing one up on
localhost would mean an open port, a `connect-src` hole in a Content-Security-Policy that is currently
`default-src 'self'`, and a second authentication surface inside a desktop app.

**The IPC boundary cannot push.** `@aibuildos/ipc` is `invoke`-only: `IpcMainLike` handles, and
`IpcClient` has exactly one method. Streaming needs a direction that does not exist yet.

**AG-UI is one-directional.** It is an event stream. A permission prompt needs an answer, and an event
cannot carry one back.

## Decision

**The bridge runs in the main process.** ACP session updates are translated to AG-UI events in main,
and only AG-UI crosses the boundary. This makes DC-0008's "the renderer consumes AG-UI only" literally
true: the agent's wire format never reaches the renderer at all.

**The boundary gains one-way, Zod-validated events**, added to `@aibuildos/ipc` the same way its
request/response half was built — as structural interfaces, so the router stays testable with no
Electron runtime ([DC-0006](dc-0006.md)). Events go main to renderer only.

**The renderer drives a custom `AbstractAgent`.** `@ag-ui/client` exposes `AbstractAgent`, whose
`run()` returns an observable of events from an arbitrary source; CopilotKit accepts agent instances
directly. The renderer subclasses it to re-emit what arrives over IPC. **No HTTP server, no open port,
no CSP change.**

**Anything requiring an answer stays a typed request.** Prompting, cancelling, answering a permission
question, authenticating, and changing a mode or model are ordinary `invoke` calls. Only the one-way
narration is an event.

**Main owns the session and the transcript; the renderer holds a projection.** A streaming interface
must accumulate as chunks arrive, and that accumulation is a rendering of events, not a second copy of
domain state — so [DC-0005](dc-0005.md) is respected rather than bent.

## Consequences

- Protocol changes land in one file in main. The renderer does not know ACP exists.
- The renderer's agent is a thin re-emitter, which is the smallest thing that satisfies DC-0008.
- The event channel is reusable: any later stream — a dev server's output, a long-running Git
  operation — has somewhere to go.
- The scripted stub agent must grow: it emits one of ACP's thirteen update kinds today, and every other
  kind this decision carries is untestable until it does ([DC-0013](dc-0013.md)).
- Two obligations the protocol states outright have to be honoured on cancel: keep accepting updates
  after cancelling, and answer any open permission request as cancelled.
- The mechanism is proven, not assumed: a custom `AbstractAgent` streaming into CopilotKit under this
  application's CSP was measured before anything was built on it. See
  [DC-0018](dc-0018.md#what-the-spike-measured).

## Alternatives considered

- **A localhost HTTP runtime in main.** The documented CopilotKit path, and the reason it was rejected
  is the open port and the CSP hole, both of which a desktop application should not need.
- **Bridging to AG-UI in the renderer.** Fewer moving parts in main, but ACP would cross the boundary
  and DC-0008's whole point — that components never see the wire format — would be lost.
- **Two-way events.** Modelling permission answers as events too. It would make the request/response
  half of the boundary redundant while losing the thing that makes it safe: a typed reply.
