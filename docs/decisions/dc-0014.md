# DC-0014 — Packaging with electron-builder, updates via GitHub Releases

## Context

A desktop application has to be installable and updatable on macOS, Windows, and Linux, with signing
and notarization on the platforms that demand it.

## Decision

Package with **electron-builder**, auto-update with **electron-updater**, and distribute through
**GitHub Releases**.

## Consequences

- One configuration produces dmg/zip, nsis, and AppImage/deb targets; code signing and notarization
  are configuration rather than custom scripting.
- electron-updater reads GitHub Releases directly, so releasing and shipping an update are the same
  act — no separate update server to run or secure.
- Releases must be published (not draft) for the updater to see them, and CI needs signing credentials
  as secrets.
- Nothing is configured in this bootstrap beyond recording the choice; packaging arrives with its own
  requirement.

## Alternatives considered

- **Electron Forge**: comparable; electron-builder's multi-target configuration and its pairing with
  electron-updater are the better fit here.
- **A self-hosted update server** (Nuts, Hazel): more control, another service to run. Unjustified at
  this stage.
