# DC-0001 — Bun workspaces as the monorepo and package manager

## Context

aiBuildOS is a monorepo: one Electron application, several shared TypeScript packages, and repo
tooling. It needs dependency installation, workspace linking, and a task runner. The predecessor
project used pnpm workspaces plus Turborepo.

## Decision

Use **Bun** as the package manager, workspace manager, and script runner. Workspaces are declared in
the root `package.json` (`"workspaces": ["apps/*", "packages/*", "tools/*"]`); cross-package
dependencies use `workspace:*`; scripts run with `bun run` and fan out with `bun run --filter`.

No Turborepo, no Nx, no separate task orchestrator.

## Consequences

- One tool for install, link, and run; no `pnpm-workspace.yaml`, no `turbo.json`.
- Installs are fast enough that a task-graph cache is not yet worth its configuration cost. If
  build times become the bottleneck, adding Turborepo later is additive and does not disturb this
  decision.
- Bun being the *runner* does not make it the *runtime* for application code — see
  [DC-0002](dc-0002.md), which is the constraint that actually bites.
- CI must install Bun and Node both.

## Alternatives considered

- **pnpm + Turborepo** (the predecessor's choice): more machinery, and a second lockfile format to
  reason about. Rejected as premature for a repo this size.
- **npm workspaces**: adequate, but slower and without `--filter` ergonomics.
