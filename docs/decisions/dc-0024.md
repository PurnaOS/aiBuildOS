# DC-0024 — PR status via the optional gh CLI

## Context

[RQ-0034](../requirements/rq-0034.md) wants a pushed branch's pull request visible in the sync
header. PR state lives behind the GitHub API, and the API means authentication — the exact
custodianship [DC-0023](dc-0023.md) just declined for git. The owner's call: use the `gh` CLI now,
as an optional binary.

## Decision

**PR status comes from `gh`, and `gh` is optional.** A new `main/pr.ts` runs
`execFile("gh", ["pr", "view", "--json", …])` — argv-only, like every other binary this
application drives — and maps the JSON to the PR chip's data. `gh` carries its own authentication;
the application stores no token and asks for none.

**Absence is data.** ENOENT resolves to `{ ok: false, code: "gh_missing" }` — a fact the interface
renders as quiet, not an error to recover from. A machine without `gh` simply has no PR chip.

**On demand only.** Status is fetched when the surface asks; there is no polling loop. The
`AIBUILDOS_GH_BIN` environment variable is the test seam, letting CI point at a stub script and
exercise both the present and the missing path.

## Consequences

- Zero token handling, zero OAuth flow, zero API client dependency; `gh auth` is the user's
  business, done once, in their terminal.
- CI machines without `gh` exercise the `gh_missing` path truthfully rather than skipping it.
- PR facts can be a press stale; the chip refreshes when asked, which matches the manual-sync
  posture of DC-0023.

## Alternatives considered

- **The GitHub API with a stored token**: rejected. It makes the application a token custodian and
  adds an OAuth or PAT flow for what one already-authenticated binary answers.
- **Polling for PR state**: rejected. Ambient network chatter for a fact the user consults at
  decision points; on-demand matches how the answer is used.
- **Requiring `gh`**: rejected. PR status is a p2 nicety; a hard dependency would tax every user
  for a chip some never look at. Absence as data keeps the feature strictly additive.
