# DC-0011 — Secrets held in Electron safeStorage, never in the bundle

## Context

Agents need credentials: model API keys, Git forge tokens, registry tokens. The OKF bundle is
committed to Git, so anything written there is published to everyone with repository access, forever,
whether or not it is later deleted.

## Decision

Store secrets with Electron's **`safeStorage`**, which encrypts against the OS keychain (Keychain on
macOS, DPAPI on Windows, libsecret on Linux). Secrets live only in the main process.

**No secret is ever written into `docs/`, into any OKF artifact, or into any file under version
control.** Agents receive credentials through the ACP layer at spawn time; they are never persisted
into the record.

## Consequences

- Secret values never cross into the renderer. The renderer sees that a credential is configured, not
  what it is.
- The main process is the only holder, which fits the IPC boundary in [DC-0006](dc-0006.md).
- On Linux, `safeStorage` availability depends on a working secret service; the app degrades with an
  explicit warning rather than silently falling back to plaintext.
- A committed-secret check belongs in the rule engine when it exists.

## Alternatives considered

- **`.env` files**: trivially committed by accident, and unencrypted at rest.
- **A third-party keytar-style native module**: `safeStorage` is built in and needs no native build
  step.
