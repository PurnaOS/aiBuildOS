# DC-0016 — Biome for linting and formatting, markdownlint for the bundle

## Context

The bootstrap shipped with no linter: `tsc` and `docs:check` were the only gates, and the absence was
recorded as an open question rather than a settled position. Type checking catches type errors; it
does not catch unused bindings, inconsistent formatting, accidental shadowing, or the drift that makes
a codebase read as though several people wrote it in different years.

The real fork was **type-aware linting**. ESLint with `typescript-eslint` can run rules that consult
the type checker — `no-floating-promises`, `no-misused-promises`, `no-unnecessary-condition` — and
this codebase is unusually exposed to exactly that failure mode: async IPC across the renderer↔main
boundary ([DC-0006](dc-0006.md)), agent child processes over stdio ([DC-0007](dc-0007.md)), and
`execa`-managed dev servers ([DC-0012](dc-0012.md)). Biome has no type information and structurally
cannot run those rules.

## Decision

Use **Biome** as the single linter and formatter for TypeScript, TSX, CSS and JSON, and
**markdownlint-cli2** for Markdown, which Biome does not process at all.

One command runs both: `bun run lint` (`bun run lint:fix` to apply fixes).

Speed and a single configuration file were preferred over type-aware coverage. Biome is one binary
with no plugin graph, no parser/plugin version matrix, and no second config to keep in sync with the
formatter.

Configuration: `biome.json` (recommended rule preset, 100-column, double quotes, organize-imports
assist) and `.markdownlint-cli2.jsonc`. Three markdownlint rules are deliberately overridden:

- `MD013` (line length) — off. Index tables are intentionally wide.
- `MD060` — pinned to `compact`, not `aligned`. Character-aligning pipes in tables whose cells carry
  several hundred characters of links would make the source unmaintainable by hand.
- `MD025` — `front_matter_title: ""`. OKF artifacts carry `title:` in frontmatter **and** an H1 in the
  body, on purpose: the frontmatter title is identity, the heading is the document. Without this
  override, every artifact in the bundle is flagged for a duplicate title.

## Consequences

- Linting is effectively instantaneous — no type-checker startup — so it can run on every save.
- One dependency for code, one for Markdown. No plugin ecosystem to maintain.
- **The floating-promise class of bug is not covered.** `void promise` and unhandled rejections in
  the IPC, ACP and preview paths will not be caught by the linter; `tsc`, code review, and the tests
  are what stand between that mistake and production. This is the accepted cost of the choice, and it
  is the thing to revisit first if a bug of that shape ever reaches `main`.
- Adding `typescript-eslint` later for type-aware rules only, alongside Biome, remains open and does
  not require unwinding this decision.
- `bun run lint` joins `typecheck`, `test` and `docs:check` in the CI gate ([DC-0013](dc-0013.md)).

## Alternatives considered

- **ESLint + typescript-eslint + Prettier**: the capable choice, and the only one that catches
  floating promises. Rejected here for the size of the toolchain — two tools, a flat-config plugin
  graph, and a type-aware pass that costs seconds rather than milliseconds.
- **Biome + typescript-eslint for type-aware rules only**: best coverage, but two linters with
  overlapping rule sets that have to be configured not to disagree. Rejected as premature; explicitly
  kept available.
- **oxlint**: comparably fast, smaller rule set than Biome and no formatter, so it would still need a
  second tool.
