# DC-0006 — In-house typed IPC router validated with Zod

## Context

Every privileged operation crosses the renderer↔main boundary. That boundary is untyped by default
(`ipcRenderer.invoke(channel, ...args)` is `any` in, `any` out), and it is the one place where a
mistake is both easy and security-relevant.

## Decision

Build a small **in-house typed IPC router** in `packages/ipc`: a channel contract where each channel
declares a **Zod** schema for its request and response, a `createRouter` for the main side, and a
typed client for the preload side. Payloads are validated on the way in and on the way out.

The router is written against **structural interfaces** (`IpcMainLike`, `IpcRendererLike`) rather than
against Electron's concrete types.

## Consequences

- One contract file is the single source of truth for the boundary; the renderer's types are derived
  from it, so a channel cannot drift from its handler.
- Because the router depends only on structural interfaces, **it unit-tests with an in-memory fake and
  no Electron runtime at all**. That is the main reason for building rather than adopting: the
  boundary is the part most worth testing and hardest to test through a wrapper.
- Zod is a runtime dependency of the main process, so it must stay Node-compatible
  ([DC-0002](dc-0002.md)).
- **Zod runs in `jitless` mode**, set once in `packages/ipc/src/contract.ts`. Zod compiles its parsers
  with `new Function`, which Electron's preload context and the renderer's CSP both forbid — the
  client side otherwise fails with *"Code generation from strings disallowed for this context"* the
  first time a channel is validated. The interpreted path costs nothing measurable on payloads this
  size, and it is what lets validation run on **both** ends rather than only in main.

## Alternatives considered

- **A third-party typed-IPC wrapper** (`electron-trpc`, `typed-ipc`): adds a dependency and a runtime
  in exchange for less control over validation and worse testability.
- **Hand-written `ipcMain.handle` calls**: what this replaces. Untyped and unvalidated.
