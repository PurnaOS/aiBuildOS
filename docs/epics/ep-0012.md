# EP-0012 — Shells and background work

Second real use put two waits on the clock: a dev server has nowhere to run, so the owner leaves
the app for a system terminal; and a long planning run holds the conversation hostage, so nothing
else happens until it ends. This epic removes both. The workspace gains a real PTY shell living in
the activity dock ([RQ-0038](../requirements/rq-0038.md), mechanism settled by
[DC-0026](../decisions/dc-0026.md)), playbooks learn to run as labelled background sessions that
share the build cap ([RQ-0039](../requirements/rq-0039.md)), and the session inventory grows the
fields that let every session — build, background task, or chat — say what it is
([RQ-0040](../requirements/rq-0040.md)).

## Scope

### In scope

- Real PTY terminals: `main/terminals.ts`, `terminal:*` channels and events, the dock's Terminals
  section, killed with the project and on quit.
- Background playbook runs: `session:start` grows `background: {label}`, one `busyCount()` caps
  builds and background runs together, dock row plus session tab per run.
- A self-describing session inventory: `label` and `startedAt` on `session:list` rows, kind
  derived and never stored, blocked background sessions discoverable.

### Out of scope

- **ACP `clientCapabilities.terminal`** — parked in EP-0004; the shell here is the user's, not an
  agent capability.
- **Terminal scrollback persistence** — a renderer reload reattaches to a blank view in v1; the
  pty lives on.
- **Supervision changes** — agent commands keep their supervision exactly as it stands; nothing
  here touches it.
