# EP-0016 — The harness, fully driven

The application drives its agents with instruction files and plain prompts while the harnesses
underneath expose far more: deterministic hooks, their own permission surfaces, advertised
commands, schema-conforming output. "Harness of harnesses" is only earned if the orchestrator uses
the orchestra. This epic closes the four gaps that matter, without opening a second door to any
agent: everything is either files the scaffolding already knows how to seed, standard ACP, or the
extension surface [DC-0028](../decisions/dc-0028.md) sanctions.

## Scope

### In scope

- Hard rules scaffolded as hooks where the harness supports them
  ([RQ-0049](../requirements/rq-0049.md)).
- Supervision mapped onto the harness's permission config options
  ([RQ-0050](../requirements/rq-0050.md)).
- Harness-advertised commands in the composer ([RQ-0051](../requirements/rq-0051.md)).
- Typed plans and verdicts over the ACP extension surface
  ([RQ-0052](../requirements/rq-0052.md)).

### Out of scope

- **An SDK sidecar** — rejected in [DC-0028](../decisions/dc-0028.md); ACP stays the only door.
- **Agent teams** — experimental and off by default upstream; watch, don't build on.
- **MCP server management** — file-side wiring that arrives with the feature that needs it
  (the Figma handoff named in [EP-0015](ep-0015.md)).
