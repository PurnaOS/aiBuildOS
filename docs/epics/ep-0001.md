# EP-0001 — Harness connection

The first product behaviour in aiBuildOS: the user attaches a coding harness and proves it answers.
Everything the product does later runs through this connection, so it is the epic that has to exist
before any of them.

Implements [RQ-0001](../requirements/rq-0001.md).

## Scope

### In scope

- The harness record and where it is persisted.
- Settings: list, add, edit, remove, with presets for the harnesses aiBuildOS ships support for.
- The first-run prompt to attach a harness when none is configured.
- A live ACP round trip against one harness — spawn, `initialize`, `session/new`, prompt, reply — with
  its failure modes reported distinguishably.

### Out of scope

- Per-harness credentials and secret storage ([DC-0011](../decisions/dc-0011.md)).
- Driving a real coding session: transcripts, tool calls, permission brokering, file access.
- Fetching the upstream ACP agent registry. Three presets are hardcoded until they go stale.
- Running more than one harness at a time.
