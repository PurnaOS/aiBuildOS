# EP-0009 — Work lands, and scales out

Accepted work still sits in the working tree; nothing in the interface can commit it. This epic
is where work *lands* — staging and committing as the user's own Git, hooks and identity and all —
and then, on that foundation, where building scales out: the worktree model
[DC-0010](../decisions/dc-0010.md) reserved, one agent per worktree, several at once, one place
showing them all.

## Scope

### In scope

- Staging, unstaging and committing from the Git tab, argv only, the user's own hooks and
  identity in force, a hook's rejection reported in the hook's words.
- Accepting a story offering a commit whose message derives from the story.
- Later in the epic: a build in its own worktree; several at once; the overview.

### Out of scope

- **Branching, pushing, pulling** — stage-and-commit first; remotes have failure modes this epic
  does not buy yet.
- **Any commit no person asked for.** Playbooks and agents do not trigger commits; checkpoint
  commits inside worktrees arrive with the worktree requirement that defines them.
