# EP-0005 — The record runs the process

The record already *describes* the process; this epic makes it *run* it. Today a state is a
dropdown, a backlog is a filter box in a rail, and what the validator knows stays in a terminal.
After this epic, the states move only along the paths their types declare, the backlog and the
work are boards where moving a card **is** the state change, and the validator's findings stand
beside the work they concern.

The organizing rule, inherited from [DC-0015](../decisions/dc-0015.md) and not negotiable
anywhere in this epic: **the record is the process state.** Every board is a live view over
`docs/`; nothing here introduces a second store, a card-position field, or a cache that could
disagree with the files.

No agent is involved anywhere in this epic. That is deliberate: the process machinery has to
stand on its own before [EP-0006](ep-0006.md) puts an agent inside it.

## Scope

### In scope

- Legal state transitions, read from the profile and enforced at the application's own save path.
- Append-only acceptance criteria enforced the same way.
- A requirements board and a work board over the record's states, where a drag is a state edit.
- Scheduling from the board: the `draft → ready` flip, made where the backlog is visible.
- Validator findings surfaced in the workspace, beside the artifact they concern.

### Out of scope

- **Enforcing transitions against agent or terminal writes.** A file changed outside the
  application is displayed as found. Policing history needs Git awareness the validator
  deliberately does not have ([RQ-0003](../requirements/rq-0003.md)).
- **Gates** — refusing a flip until tests pass. That arrives with the test-run loop, as its own
  requirement.
- **Change impact and re-planning.** A record-graph feature, but it needs the plan machinery of
  [EP-0006](ep-0006.md) first; it gets its own requirement when its wave opens.
