# EP-0010 — The workspace keeps up with the work

The first epic born from real use rather than the vision doc. Five complaints from the owner's
first sessions with a live agent, and a review that traced each to its cause: states that never
move because conversational work has no path into the walk; files that never appear because
nothing watches the filesystem; a fresh project that hands a real agent no instructions at all; a
rail that stops being scannable as the record grows, with no sign anywhere that work is
happening; and command execution rendered as a title and a coloured bar.

Three of the causes were defects in verified work — [BG-0006](../bugs/bg-0006.md),
[BG-0007](../bugs/bg-0007.md), [BG-0008](../bugs/bg-0008.md) — absorbed here the way EP-0004
absorbed its own.

## Scope

### In scope

- Watching the project (DC-0022): every change visible within a debounce, whoever made it.
- The record following conversational work: "Work on this" walks a ready story, instructions
  teach any agent the state discipline, and the build playbook finally says what DC-0021 promised.
- Root `AGENTS.md`/`CLAUDE.md`, seeded and dogfooded.
- A rail that collapses by group and counts what it holds; the chrome findings the review ranked.
- Work in motion made visible; a transcript command that reads like a terminal.

### Out of scope

- **Watching worktrees** — the review surface and Now's "works in its own copy" line carry that.
- **Virtualizing the rail** — scannability fails first; windowing waits for a record that
  actually measures slow.
- **Gates and everything else already deferred by name** in earlier epics.
