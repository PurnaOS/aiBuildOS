# EP-0006 — The loop: pick, plan, build, accept

The journey the vision doc promises ([How aiBuildOS works](../HowItWorks.md), steps 4–7 and 10),
closed end to end for the smallest honest case: **one user, one agent, one working tree.** Pick
ready requirements, get a plan proposed, shape and approve it, watch a story build, and accept
the result — every step of which is a state in the record, because approval, scheduling and
acceptance *are* state changes ([EP-0005](ep-0005.md) made them trustworthy).

The leverage piece is the playbook: plan-proposing, building, and every other standard step is a
prompt the project itself carries as an ordinary committed file. The application adds buttons; the
instructions belong to the project, so any tool — this one or another — reads the same rules
([DC-0019](../decisions/dc-0019.md)).

## Scope

### In scope

- Playbooks as record artifacts: seeded on scaffold, listed as buttons, composed with the
  artifacts the user selected, sent visibly through the conversation.
- Picking ready requirements and starting the plan playbook with exactly those as context.
- The plan as draft Story and TestCase artifacts written by the agent, gathered into one view,
  editable, and approved by state flips the record's own rules police.
- Building one story: the build playbook, the `ready → queued → building → review` walk, a review
  surface holding the story, its criteria and the working-tree diffs side by side, and the
  accept / send-back verdict.

### Out of scope

- **Parallel builds and worktrees** ([DC-0010](../decisions/dc-0010.md)) — the loop closes in the
  main working tree first; several agents at once is its own epic.
- **Committing to Git from the interface.** The built changes stay in the working tree the Git
  tab already shows; writing to Git has its own failure modes and earns its own requirement.
- **The intake interview and structured asks** — the conversation surfaces have their own epic.
- **Running the project's checks.** Review here reads diffs against criteria; the test-run loop
  is its own requirement.
