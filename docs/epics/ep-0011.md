# EP-0011 — Git end to end

Second real use showed git handling stopping at the water's edge: the application branches, commits
and merges locally, but pushing, pulling, and watching a PR still mean leaving for a terminal; a
batch of related stories has no shape of its own; and the worktrees doing the building are nearly
invisible — an interrupted build cannot even be picked up again ([DC-0021](../decisions/dc-0021.md)
named that gap and deferred it). This epic closes the loop: remote sync through the user's own git,
branch and PR visibility where the work is, sprints as branches with their own worktrees, and
worktrees you can see and resume.

## Scope

### In scope

- Remote sync — fetch, pull, push — manual, through the user's own git and credential chain
  ([DC-0023](../decisions/dc-0023.md)).
- Branch and sync visibility: a sync header on the git pane, ahead/behind per branch.
- PR status through the optional `gh` CLI, absence as data ([DC-0024](../decisions/dc-0024.md)).
- Sprints: a batch of stories as a first-class artifact, bound to a branch with its own worktree,
  stories building in parallel off it ([DC-0025](../decisions/dc-0025.md)).
- Resuming a build in its surviving worktree; worktree state visible with a Resume action.

### Out of scope

- **Auto-anything** — no auto-push, no auto-fetch, no PR polling; every sync is its own press.
- **Merge or rebase pulls** — pull is `--ff-only`; divergence fails in git's words.
- **Token storage or a GitHub API client** — `gh` present or absent is the whole story.
- **Terminals, background runs, and the workspace redesign** — EP-0012 and EP-0013 carry those.
