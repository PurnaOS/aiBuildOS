# EP-0004 — The project workspace

Where the product becomes itself. [EP-0001](ep-0001.md) attached an agent and proved it answers;
[EP-0002](ep-0002.md) gave the product a project to work on. Neither did any work. This epic is the
place the work happens: a conversation with a coding agent, the record on one side, the files on the
other, and the ability to change both.

Implements [RQ-0004](../requirements/rq-0004.md), [RQ-0005](../requirements/rq-0005.md) and
[RQ-0006](../requirements/rq-0006.md) — the last of which was excluded below until it earned the
requirement that exclusion asked for.

The design is settled before the code is written, and the requirements stay `draft` until it is — a
draft requirement yields an empty queue on purpose, which is how
[requirement-first](../guidelines/requirement-first.md) says scheduling works.

## Scope

### In scope

- A streaming channel from the main process to the renderer, which does not exist today.
- An ACP session held open across messages, replacing the one-shot probe.
- The conversation: streamed replies, reasoning, tool calls, diffs, plans, token usage.
- Everything the agent asks for — permission, structured input, authentication — answered with the
  options the agent itself advertised.
- Everything the agent offers as control — modes, models, effort, commands — driven from the agent.
- Cancelling a turn, honouring the protocol's obligations about updates still in flight.
- The record panel, the file tree, the Git changes panel, and a tabbed centre.
- Editing files, and authoring artifacts through the profile without destroying their diffs.

### Out of scope

- **Parallel agents.** One session per project. Several agents on several branches at once is the
  worktree model in [DC-0010](../decisions/dc-0010.md) and needs its own requirement.
- **Staging, committing, branching or pushing from the interface.** Writing to Git has its own failure
  modes — hooks, signing, identity — and earns its own requirement.
- **Brokering filesystem and terminal access for the agent.** The client advertises no such
  capabilities, so agents do their own I/O; adding them means implementing the handlers behind them.
- **Persisting a transcript across restarts.** A conversation lives as long as the application run;
  reloading history is `session/load`, and it arrives when it is needed.
- **Previews of the running application** — that is [DC-0012](../decisions/dc-0012.md), separately.
